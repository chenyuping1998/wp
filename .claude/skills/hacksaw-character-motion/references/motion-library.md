# 動作庫：挑一隻角色的動作，原封不動套到你自己的角色上

## 先挑角色

```
gallery/index.html                       ← 瀏覽器打開：六隻角色、每段動作一張 GIF
python spineplay/motionlib.py --list     ← 帶編號的清單，之後 -c 1～6
```

GIF 是**真正的動作資料**在演 —— 網格怎麼彎、什麼時候換臉換道具、裁切，
全部照原作；每個零件用它自己網格形狀的色塊代替美術，**沒有任何原作像素**。
顏色代表部位：膚色＝頭臉、橘＝頭髮、藍＝身體、綠＝手臂、紫＝腿腳、
金＝道具、白＝對話框、半透明＝煙／光。

| # | 角色 | id | 動作 | 簡單路線 | 完美路線 |
|---|---|---|---|---|---|
| 1 | 白西裝老大 | `miami_boss` | 2 | 一張全身圖 99.70% | ＋零件圖層 99.76% |
| 2 | 扛球棒男 | `miami_main_guy` | 4 | 一張全身圖 99.69% | ＋零件圖層 99.78% |
| 3 | 扛球棒女 | `miami_main_girl` | 5 | 一張全身圖 98.98% | ＋零件圖層 99.84% |
| 4 | 比基尼女 | `miami_bikinigirl` | 4 | 一張全身圖 99.66% | ＋零件圖層 99.81% |
| 5 | 綠背心壯漢 | `miami_green_guy` | 4 | 一張全身圖 99.63% | ＋零件圖層 99.91% |
| 6 | 浣熊大盜 | `le_bandit_raccoon` | 21 | 每個零件一張圖 99.98% | （一張全身圖只有 77%）|

**百分比是怎麼來的**：拿原作自己當輸入，跟原作的動畫逐格比，取所有動作裡
**最差的一格**（輪廓重疊度 IoU）。也就是「你的圖照規格畫到完美，最多能到這裡」。
`--spec` 與 `--list` 都會印出來。

---

## 「完美」到底是什麼意思

| 項目 | 狀態 |
|---|---|
| 骨骼動作 | 跟官方 spine-ts runtime 差 **1e-7** |
| 網格變形（含 deform）| 跟原生播放器差 **5e-5**（`--verify` 每台機器都能驗）|
| 畫面（零件都補齊時）| 99.76–99.98%，剩下的是兩次光柵化的**邊緣抗鋸齒**（次像素）—— 跟這個播放器對官方 runtime 的差距同一個等級 |

你畫的是**你自己的角色**，成品當然不會長得像原作。「完美」是指：
**動作完全是原作的，而且你的圖不會破、不會殘影、不會露洞。**

## Miami 五隻：一張全身圖（＋要完美就補零件圖層）

### 原理：網格投影

pack 帶著原本的網格：每個頂點綁哪幾根骨、權重多少、bind pose 在哪、
三角形怎麼連、deform、clipping。你的圖對齊到 bind pose 之後，**每個頂點的 uv
＝它的 bind pose 位置投影到你的圖上**。動起來時頂點照原本的權重跟骨頭走，
你的像素跟著頂點走 —— 這就是 Spine 本來的做法，只是貼圖換成你的。

### 簡單路線

```bash
python spineplay/motionlib.py -c 1 --mask ref.png               # bind pose 剪影
python spineplay/motionlib.py -c 1 --mask ref_named.png --outline
python spineplay/motionlib.py -c 1 --prompt
# 生一張全身圖 —— 最穩的做法：把 ref.png 當 ControlNet 或 img2img 起始遮罩
python spineplay/motionlib.py -c 1 --checkpose 全身圖.png
python spineplay/motionlib.py -c 1 -a full_screen/idle --image 全身圖.png --gif out.gif
```

**規則跟切層相反**：四肢**不用**跟身體分開，長大衣、圍巾、披風都可以 ——
只要剪影跟 `ref.png` 一樣。`--checkpose` 對齊之後逐一檢查每個零件的位置上
你的圖有沒有東西，落空的會說在哪（離腳底幾 %、從左幾 %）。

### 完美路線：補零件圖層

一張圖裡，**被別的零件擋住的地方是空的**。耳環一晃、手一抬，後面那塊就露出來，
而且前面的零件會把背景一起帶著晃（殘影）。這是一張圖到不了 100% 的唯一原因。

```bash
python spineplay/motionlib.py -c 3 --split 全身圖.png --out 補圖/
```

會依必要性列出要補哪些零件：

1. **換裝件** —— 全身圖裡根本沒有，動畫會換上它（一定要畫）
2. **會被露出來的** —— 前面的零件一動，被擋住的地方就露出來
3. **會晃動的** —— 要有自己的圖層，才不會把背景一起帶著晃

每個零件給：`<零件>__area.png`（白＝零件範圍、紅＝被擋住要補畫）、
`<零件>__start.png`（起始稿）、README.md 裡有給生圖模型的指示。
補好的圖層**跟全身圖一樣大、零件在原位、其餘透明**，檔名＝零件名.png：

```bash
python spineplay/motionlib.py -c 3 -a full_screen/idle --image 全身圖.png --parts 補好的/ --gif out.gif
```

**有給的零件用自己的圖層、沒給的沿用全身圖** —— 可以只補一部分先看效果。
實測 main_girl（耳環、髮絲會晃）：一張圖 98.98% → 補齊 **99.84%**。

## 浣熊：每個零件一張圖

浣熊的 21 段動作要用到 **38 張零件圖**（各種表情、嘴型、法文對話框、麵包、帽子；
帽子跟錢幣各有兩個位置共用同一張）。一張圖只有一張臉，給不出那些 —— 實測一張圖只有 77%。
skin 裡另外還有 5 個對話框字（cava、merci、oui、bleep、non），21 段動作都沒讓它們
出現過（逐格播過確認），**不用畫**。

```bash
python spineplay/motionlib.py -c 6 --guide --out 零件指引/     # 38 張輪廓範本＋每個零件的提詞
# 照 零件指引/README.md 一張一張生，檔名＝零件名.png，放進同一個資料夾
python spineplay/motionlib.py -c 6 --layers 零件/ --checkart    # 逐張檢查
python spineplay/motionlib.py -c 6 -a idle --layers 零件/ --gif out.gif
```

`--guide` 給的東西：

* `<零件>__shape.png` —— **輪廓範本**：白色＝這個零件的形狀，外面透明。
  生圖時跟角色設定圖一起附上（或當 ControlNet／img2img 的遮罩），照它的輪廓畫。
* `<零件>__joints.png` —— 同一張範本標出兩個關節（紅＝軸心、藍＝骨頭方向），
  只有要用自己的形狀、手動對位時才用得到。
* `README.md` —— 每個零件是什麼、哪幾段動作看得到它、方向規則、給生圖模型的提詞。
* `_bind_pose.png` —— 所有零件的色塊擺在 bind pose 上，看各部位的大小比例。

**照範本的輪廓畫，`--checkart` 一定會過** —— 建包時門檻就是拿範本（轉過、縮過、
加留白）一起校準的。規則只有四條：

1. **大小不用管**，接上去會自動縮放。
2. **角度也不用管**：每個零件轉幾度都行，接上去會自動轉正（README 的「方向」欄
   全部是「任意角度」；只有對話框的字要橫著寫）。
3. **不要左右翻**。畫反了 `--checkart` 會直接說「翻過來就對了」。
4. **對話框的字寫你自己的**：範本是比例正確的框（不帶原作的字），只檢查長寬比（±20%），
   要橫著寫。

`joints.json` 現在用不到了（以前那兩個「太對稱要給座標」的零件，其實只是分不出鏡像；
不接受鏡像之後就判得出來）。

> ⚠️ **輪廓範本就是原作每個零件的外形**（64×64 黑白格子，沒有顏色、沒有細節）。
> 照著畫出來的角色，剪影會跟 Hacksaw 的浣熊一樣 —— 研究、實驗沒問題；
> 要變成你自己的作品，外形得換成你自己的設計（大致落在原本零件的範圍裡就好，
> 超出去的會被切掉）。那時候 `--checkart` 的形狀檢查本來就會擋（它比的是原作的形狀），
> 對位改用 `joints.json`：`--guide` 另外給 `<零件>__joints.png`，紅點＝軸心、藍點＝骨頭方向，
> 在你的圖上找到對應的兩點寫進去，再 `--layers 零件/ --joints joints.json`。

### 實測

| 輸入 | `--checkart` | 接上骨架的準度 |
|---|---|---|
| 輪廓範本本身 | 38 / 38 通過 | **1.0000** |
| 範本亂轉（字 ±60°、其他任意角度）、亂縮放 0.6–1.5 倍、加 30% 留白 | 38 / 38 通過 | 0.9919（平均 0.9940）|
| 原作零件 | 38 / 38 通過 | 1.0000 |
| 原作零件亂轉亂縮 | 38 / 38 通過 | — |
| 單軸拉長 1.3 倍 | 30 / 30 擋下 | — |
| 中段彎 10% | 30 / 30 擋下 | — |
| 左右翻過的範本 | 28 / 30 擋下（27 張明說「左右相反」；另外 2 張本身左右對稱）| — |

「準度」＝你的零件被貼上去的位置，跟**正確的貼法**（直接用原作零件圖在骨架上的
位置）比，21 段動作逐格的輪廓重疊度，取最差的一格。亂轉亂縮那一列剩下的 0.8%
是把圖旋轉、縮放重新取樣時邊緣像素的變化，不是貼錯位置。拉長／彎折／鏡像那三列是
刻意畫錯的樣本，30 張＝扣掉 8 張對話框字（那些只檢長寬比）之後的零件。

pack 存了每個零件「原作零件圖的框放在骨架哪裡」（仿射，45 個位置殘差全部 < 0.14 像素）、
原作零件圖跟輪廓範本兩套形狀座標系，你的零件會對上比較像的那套、再投影到網格上 ——
**網格變形完整保留**。原作零件當輸入是 **99.98%**（跟原生播放器比）。

## 換一台機器之後先驗

```bash
for c in 1 2 3 4 5 6; do python spineplay/motionlib.py -c $c --verify; done
python spineplay/motionlib.py --gallery      # 重新產生 GIF 示意圖（不需要任何原作素材）
```

每個 pack 帶兩組黃金值，都是用讀原始骨架檔的原生播放器產生的：骨骼世界矩陣
（原生播放器又跟官方 runtime 對過）與網格頂點（含 deform）。這台機器用 pack
重算，兩組都要一致才印 `✅ motion pack verify OK`。

## 舊版為什麼複製不了（這版之前的錯，都是我的）

1. **方法錯**：舊版把網格當矩形硬貼（剛性片）。Miami 的角色是連續網格＋多骨權重，
   就算用原作的圖、切得完美，跟原生比只有 43–57%。
2. **驗證錯**：舊版寫的「忠實度 99.997%」是拿我的方法跟我另一個方法比，
   自己跟自己比，從沒跟原生比過，所以上面那個錯被蓋住了。
3. **建議錯**：舊版叫你「不要長大衣、圍巾，手臂要跟身體分開」—— 那是切層的規則。
   白西裝老大本身就穿長大衣、披毛領、雙手垂在身側。
4. **浣熊沒保留網格變形**：舊版浣熊是 88%，現在 99.98%。
5. **浣熊的提詞跟路線矛盾**：`--prompt` 還在叫你生一張全身圖再切（「不要長大衣、
   四肢要分開」那套），但浣熊走的是每個零件一張圖；而且沒有零件的輪廓可以照著畫。
   現在 `--guide` 給 38 張輪廓範本，照範本畫一定過 `--checkart`。
6. **叫人畫了動畫裡不會出現的零件**：浣熊 5 個對話框字、老大 1 塊身體，skin 裡有
   但沒有任何一段動作讓它們出現。現在每個清單都是逐格播過、真的看得到的才列。

## pack 裡有什麼、沒有什麼

| 有 | 沒有 |
|---|---|
| 骨骼、約束、關鍵幀、曲線、deform | 貼圖、atlas |
| 網格幾何：頂點、權重、三角形、clipping 多邊形 | **uv** |
| 零件圖框的仿射（6 個數字）、形狀座標系 | 任何一個像素 |
| 零件輪廓的佔有格（10×10 簽章、64×64 範本用；黑白兩值，沒有顏色）| — |
| 美術外框、剪影分段數、覆蓋率基準、會晃的零件清單 | — |
| 黃金值（驗證用）| — |

頂點與粗略輪廓格大致描出了原角色每個零件的形狀，這點要知道；uv、貼圖、
任何像素都沒有。
