# 分層加權網格角色：做法與踩過的坑（Turf War v6，2026-11-09）

適用：角色已交付成少數幾張分層圖（頭／身體含腿／前手臂／後手臂，各自完整補底），要做到「專業老虎機水準」的動作，而且**每個接縫都要自然**。工具在 `wp/apps/TurfWar/design/cast_v6/`，第一次用就照這份做，不要從頭摸索。

重建一行（python 用 /Applications/anaconda3/bin/python3）：

```
python design/cast_v6/build_v6.py && python design/cast_v6/assemble.py && node design/cast_v6/finalize.mjs --install
```

`build_v6.py` 產生骨架＋網格＋權重（`SPEC` 是每隻角色的關節點、袖縫折線、物理配件）；`motions.py` 寫動作；`assemble.py` 合併並自動 key 輔助骨；`finalize.mjs` 選腿 IK 方向、驗 setup pose 回到原圖、量包絡、安裝。播放邏輯在 `src/game/castDirector.ts`（遊戲與 QA 共用同一個類別）。

## 做法

1. **骨架自己建，不用 kit 的**：hip→spine→chest→neck→head、左右鎖骨（聳肩、出拳時肩膀前送）、手臂三節、雙腿兩節＋IK、鞋子 `noRotationOrReflection` 釘地。關節點**放在畫出來的關節中心**（見坑 17），不是輪廓邊上。
2. **權重＝每張圖自己網格上的 harmonic（Laplace）場**，只在骨頭「核心」釘值，關節處自然平滑過渡。核心要用**最近骨段（own-segment）＋ 25px 以上緩衝**來判，兩組釘點不可相鄰。
3. **接縫規則**：上層圖畫在**同一個部件**上時（MG 膨袖、FG 袖肩畫在身體圖上、壓著手臂），上層那塊抄下層的權重，兩層一起動，邊緣不會滑開。**不同衣片**（外套前片、背心蓋住袖子根部）不要抄，讓袖子在底下滑，但底下要有夠長的隱藏根部。
4. **袖縫折線 `armholeF`**：沿畫出來的真正袖縫走，袖下要繞到軀幹外。軀幹側（外套前片、背心）跟胸，袖側跟手臂。
5. **半轉輔助骨**：`deltF` 由 assemble 自動 key 成上臂的一半，肩頭範圍釘給它。抬手時肩頭會圓圓地轉，不會凹陷。
6. **物理配件**（帽繩、鍊子、領帶）用 Spine 4.3 physics，參數加 `limit`。權重遮罩用**配件本身的像素**，不要用膠囊形狀。
7. **動作節奏**（照 Iron Jaw 三星）：
   - idle 2 秒正弦，每往外一節晚 0.067 秒。
   - 反應：蓄力約 0.3 秒、出手約 0.1 秒、停頓、收回。
   - 出手時軀幹用 `drive` 先帶後到，手臂才用 `snap`，鎖骨跟手臂同一節奏。
8. **播放**：idle 一直在 track 0 播，從頭到尾不重來；反應在 track 1，混入 0.12 秒、混出 0.25 秒，接回 idle 當下的相位。反應進行中又來新的反應時**排隊**，等收勢再接，不要半路切掉。
9. **閘門** `check_spine_motion_cast.mjs`：用同一個 director 跑完整範圍：
   - 全部動作；
   - 每種反應 × 被打斷 × 不同 idle 相位 × 1/2 倍速；
   - 24 秒連續 idle，物理開著。

   壓扁或翻面的三角形只有在被上層圖完全蓋住時才放行（`design/lib/cast_occluded.py` 量覆蓋率 ≥0.98）。
10. **大小不能變**：側邊人物的縮放由動作包絡寬度決定。包絡寬度要等於上一版。量法：`envelope_by_clip.mjs`；在遊戲裡用 `__PIXI_APP__` 找 `turf-cast-base` 的 scale，新舊版本在 4:3、16:10、16:9 各比一次。

## 驗收順序（每次改權重或動作都要從頭跑）

1. `tri_scan.mjs <rigDir>`：找最差的三角形（不要用 grep 把 arm_far 濾掉，坑 19）。
2. 找到的三角形用 `tri_time.mjs`／`trace_mix.mjs` 看是哪一格、哪根骨頭造成的。
3. 用 `render.py --scale 2 --crop …` 放大看實際畫面；需要時配 `--tex` 只看單一圖層。
4. 跑 `check_spine_motion_cast.mjs`（遊戲 build 也會跑）。
5. 用 `analyze.py` 看頭部每格的最大速度，抓一格跳很多的跳點。
6. 實機：桌機中獎、`forceBook=11` 觸發 FG 開場與 Kingpin、直式 390×844。
7. 給使用者看 `compare_gif.py` 產生的新舊並排實速 GIF。

## 踩過的坑（症狀 → 原因 → 修法）

1. **近手繃帶被拉扁成一團** → 用直線距離判斷「肩膀根部」，結果壓在胸前的手腕也被算進去，綁到了胸口 → 改用**網格上的測地距離**來判。
2. **出拳時外套拉鍊、前片拉成黑色鋸齒** → 袖縫線放在拉鍊上，外套前片被當成袖子 → 線沿實際袖縫走，袖下繞到軀幹外側。
3. **FG 背心側邊在腋下被扯成尖刺** → 同上：袖縫線下段在背心裡面 → 下段改走背心外緣。
4. **MG 膨袖權重忽高忽低（0.99／0.85 相鄰），勾拳時翻面** → 手臂圖在膨袖底下沒有上色，那些點沒抄到手臂權重 → 袖側一律抄手臂權重（沒上色處用最近點外推），再平滑一次。
5. **轉頭時帽子出現一條直線切痕** → 帽子背面一半綁胸、一半綁頭，兩組相鄰 → 頭圖下的帽子／領口綁 `neck`（臉在帽子裡轉，像真的連帽衣）；臉部核心要離 neck 區 50px 以上。
6. **任何兩組釘點相鄰都會變成硬台階** → 兩組之間至少留 25px 讓 harmonic 過渡。
7. **抬手超過約 40° 時肩頂凹一個 V** → 這是線性混合在彎曲內側塌陷 → 加 `deltF` 半轉輔助骨；過渡長度要和到樞紐的距離相稱（半徑 100px 的地方要約 80px 過渡）。
8. **手肘伸直 90° 時手肘背面壓扁或翻面** → 畫成緊折的手肘往回伸，袖口會撞進肘後堆起的袖子 → 伸直只做到 70–80%，前臂不拉長。加肘部半轉輔助骨試過，反而更糟（問題不在弦長），已撤掉。
9. **出拳時上臂前面被拖動** → 緊折的手肘讓前臂和上臂貼在一起，前臂權重沿折痕漏到上臂（離手肘 100px 還有 15%）→ 離手肘 60px 以外、明確在上臂側的地方，清掉前臂和拳頭的權重。
10. **外露的袖子帶著胸口權重（35–49%）** → 隱藏根部抄了身體權重，再被 harmonic 擴散出去 → 外露的袖子清掉胸、腰權重；隱藏根部只算「被身體蓋住、且離外露處 34px 以上」的部分。
11. **出拳第一格頭部瞬移 85px** → 軀幹也套了 snap 曲線 → 軀幹改用 `drive`，出手前 0.03 秒先動、出手後 0.04 秒才落定。
12. **細帽繩物理翻折連帶衣服**；turbo 時擺幅加倍 → 擺幅一定要小於 falloff 寬度 → 降低 rotate、加寬 falloff，physics 加 `limit` 300–350。
13. **領帶尖端把皮帶和褲子拖出一條折痕** → 用膠囊形狀當權重範圍，圓頭蓋到皮帶上 → 改用領帶自己的橘色像素當遮罩；尖端本來就貼著皮帶，所以兩端固定、只讓中段擺（鍊子也一樣）。
14. **連續中獎時姿勢混出怪形** → 反應被下一個反應半路切斷，兩個動作的中間姿勢互相混合 → director 排隊處理。
15. **蓄力、護手時肘彎翻面** → 動作把手肘折得比原圖還緊 → 任何蓄力、護手、待機都不可以讓前臂往更折的方向轉（local 值要 ≤ 原圖）。
16. **慶祝時拳頭跑到頭後面** → 遠側手臂在頭的圖層底下（違反「拳頭一律在頭前面」）→ 改往側上方舉拳，避開頭部範圍。
17. **小腿中段不自然彎曲**（Stone 截圖）→ 膝蓋骨頭比畫出來的膝蓋低 80–120px，加上大腿到小腿的過渡拉太長，小腿彎成香蕉形 → 膝蓋放在畫的膝蓋中心；大腿核心 t 0.24–0.78、小腿核心 t 0.24–0.88，各自保持直。**關節點一定要對著畫面上的折痕放**，這次手肘、膝蓋都在這裡吃過虧。
18. **出拳加長後人物小了 6%** → 動作包絡變寬，側邊縮放自動縮小 → 收短出拳，讓包絡與上一版同寬，並在遊戲裡量 scale 確認。
19. **檢查器漏報** → 我用 `grep -v arm_far` 濾掉被身體蓋住的翻折，結果連看得到的也一起濾掉了 → 不要濾掉；交給 `cast_occluded.py` 判斷到底看不看得到。
20. **工具本身拖垮這台 8GB 的機器** → tri_scan 把每格每個三角形都存進陣列；渲染器用 fork 多程序，加上 OpenCV 執行緒會卡死 → 只保留每個三角形的極值；渲染改單程序、貼圖先縮到輸出大小。
21. **Spine 4.3 API 差異** → `getCurrent` 改名 `getTrack`；`addEmptyAnimation(track, mix, 0)` 會自己算 delay，不要再手動覆寫。
22. **上傳**：與上一版位元組相同的 PNG 直接沿用舊檔，平台會在伺服器端複製，不用重傳；`start_upload` 要同時給 plan_id 和 team／game／type／path。
