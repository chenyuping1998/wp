# 生圖需求單與收圖驗收：第一版就寫完整，收圖當天就驗完

退件最多的就是這一段。Static Shift 的角色從 r1 做到 r7.1（8 版）、Dragon Tide 的拆層從 R1 做到 r12（約 12 輪、5 天）、相撲猴的角色從 10-24 修到 11-10。回頭看，每一輪的原因都能在開單當天或收圖當天擋掉。這份把擋法寫成清單。

## 1. 分工

**Codex（生圖端，Stone 說的「摳爹」）只生圖。其他全部 Claude 做。**（Stone 11-07、11-09）

| 誰 | 做什麼 |
|---|---|
| Claude | 寫需求單與每張圖的提示詞（每張一個 txt）、準備輸入圖／上下文截圖／遮罩；收圖後對位、去背、拆層、補底、合成、清碎點與白邊、跑檢查、套動作逐格看、出對照圖與 GIF、寫驗收紀錄 |
| Codex | 輸入圖＋提示詞 → 生圖 → 交回**原始生成圖**（可多生幾張候選） |
| Stone | 看定稿（畫風、全身姿勢與體型）、平台上的手動步驟 |

- 單子裡**不放**給生圖端的自查清單，不要求它去背、透明、裁切、對位、修圖、拆層、跑檢查、寫報告。「收圖要看什麼」寫在單子的 Claude 紀錄段。
- 生圖端自評的 PASS 不算驗收；Claude 一律在原生解析度獨立重看。
- 沒有通往 Codex 的管道：要給它的話寫成一段完整訊息，請 Stone 貼過去。
- Codex 自己開的單（提示詞、項目清單）先由 Claude 對過再用：Wild Alchemy batch 2 用了「學徒／小徒弟」畫出未成年；batch 3 漏了遊戲實際載入的 13 項。

## 2. 開單前要先定的事

沒定就開單＝之後整批重生。

1. **畫風定錨**：先過 style frame（H1、一張小圖、Wild、背景局部、角色的頭，合成在真盤面與 200 px），Stone 點頭後才開批次（SKILL.md step 3）。Dragon Tide 第一批沒走這步，龍王、龍女、符號三種畫風，全部重生。
2. **角色先定動作，再定姿勢**（`spine-character` 第 0 步）。動作表每列寫「遊戲裡什麼時候播」；不會播的不做（Dragon Tide 的 win_big、cast_empty 做了沒用）。同時列出每個動作要的換手圖、道具、帽子／眼鏡。
3. **模板做得到嗎、遊戲怎麼跑它**：用哪個模板（拳擊架式、stand34 站姿、stand34 長袍持杖；位置見 `spine-character`「模板在哪」）；遊戲用 Spine 4.3 直跑還是烘焙（問 Stone，Static Shift 中途改過）。
4. **姿勢的硬傷先排除**：
   - 叉腰（手在髖、肘外張）的那隻手不排任何舉過肩的動作（前臂會繞 180°；催眠猴修了 4 次）。
   - 拿道具的手：拳＋腕＋道具畫在同一層，或讓袖口蓋住手腕（Dragon Tide 龍王手腕露在袖外，來回 4 步）。道具要能越過頭飾（龍王三叉戟舉不過龍角）。附握點與道具角度。
   - 不要 A-pose／T-pose；手臂要是動作中的自然姿勢。四肢不貼身、兩腿不交叉。
   - 朝向寫明（站盤面哪一側、臉朝哪）。
5. **體型用數字寫**：上臂、前臂、大腿、小腿、軀幹的寬度各是頭寬的幾成（相撲猴「四肢太細」：上臂 0.34 頭、前臂 0.2 頭；酸黃瓜廚師「太瘦」再「肩太寬」）。
6. **全身定稿圖先給 Stone 看姿勢、體型、年齡、著裝，點頭後才拆層。** 姿勢或體型不對就重生全身圖：不用程式角度硬補超過一輪（Turf FG 補了 4 輪後整隻重生），不用像素拉寬改體型（相撲猴試過，排線糊掉）。
7. **項目清單從程式清點**：這批圖的項目＝`assets.ts` 逐鍵對過，加上需求單各節；不是憑印象列。
8. **成年**：角色名、形容詞、提示詞先掃一次（`scripts/preflight.py --docs <需求單資料夾>` 會掃）。

## 3. 每張生圖單的固定欄位

| 欄位 | 寫什麼 |
|---|---|
| 用途 | 哪個遊戲、畫面上哪裡、顯示多大（像素） |
| 畫布與安全邊 | 尺寸；主體離邊至少幾 px（龍女 v2 畫出畫布）；背景 1920×1080（曾交 1672×941） |
| 去背色 | 指定一個不在調色盤裡的顏色（品紅）；不用白、灰、棋盤格。透明由 Claude 做 |
| 畫風塊 | ART_BRIEF §0 的那段英文，逐字貼在提示詞最前面 |
| 輸入圖 | 定錨圖、母圖、姿勢參考；局部補畫附「原座標的上下文截圖＋目標遮罩＋尺寸」 |
| 禁止 | 文字與數字（由程式排）、品牌相似物（三條紋、圓標、特定縫線）、烤進去的光暈與陰影、未成年、裸露、會被誤認的形狀 |
| 顯示時的底 | 這張圖會放在什麼顏色上（符號的底卡色、徽章色、背景色）。Static Shift 的麥克風指定成靛藍，放在薰衣草底卡上糊在一起 |
| 候選 | 要幾張候選（由 Claude 挑） |
| Claude 紀錄段 | 收圖要量什麼、要看什麼（不是給生圖端的） |

## 4. 各類素材的必寫規則

**角色母圖／圖層**（細節在 `需求單範本.md`，那裡有「以前退過件的問題」表）
- 先一張完整全身圖；被擋處畫完；關節兩邊重疊、重疊處不描邊、多畫的部分不超出相鄰部件外緣；露在透明旁的邊一律墨線；關節不切平、不用直線修。
- 身體層畫了袖肩時，壓在手臂上的那段不描邊。拳套與道具整顆畫完、疊在頭前面。
- 這隻角色的高風險部位點名寫出來：腋下、袖內、被道具或手擋住的腰後、尾根、脖子、腕、膝。
- 證據角度：站姿之外要伸直 0°、舉過頭、屈膝張腿（褲襠、膝的缺陷只在這些角度出現）。

**局部補畫**（第二階段）
- 遮罩由 Claude 畫，用「前面那個部件的完整輪廓外擴」，不是只開在關節（相撲猴的後手拳套後面、褲襠後面是空的）。
- 同比例上下文：Dragon Tide 的拳頭＋手腕補畫回來放大 1.5 倍、畫法不同，作廢。收圖先量比例與位移（相撲猴一條大腿位移 190 px）。

**符號**
- 大圖騰有框，和小圖同款同大小。每個符號寫它的待機動作與支點（鍊子要有清楚的掛點、車要有輪子）。
- 寫最小佔格比並在收圖時量（ink bbox ÷ cell）；同級符號寬度差設上限（相撲猴 A／J 太窄；Static Shift 的 Wild 細桅杆只佔 40%）。
- 亮度階梯在 style frame 就量：小圖 < 人物／大圖 < 特殊符號 < WILD（Wild Alchemy：≤80／95–110／…／≥145）。WILD 要最顯眼。
- 帶數值的符號：每一階的字色對它的底色，在最小格尺寸看得到。
- 70 px 下會被看成什麼（酸黃瓜的 H4 像大麻葉）。

**背景**
- 交件拆物件層：每個會動的東西一張 PNG，共用 1920×1080 畫布；清單先寫好（`new-games/wild-alchemy/SPEC.md` §3.1）。
- 盤面後面、角色後面不放會動或細碎的東西；角色站的那一側整體往紙色退。

**框、底板、按鈕、數字組**
- 盤面框的洞口比例＝盤面比例（Dragon Tide 交 1146×857，不是 6:5，只好改九宮格）。
- 面板要留一塊乾淨的字區，標出範圍；數字不壓圖。
- 數字組每個字同一個畫布尺寸；`.`、`,` 在基線上。
- Buy Bonus 的下注列按鈕和彈窗卡片是兩個素材；hover 要有自己的亮版。每款有自己題材的購買圖示（64 px 看得懂）。
- 首批就要含：框、小圖、logo、下注列底板、開場卡。這些沿用來源遊戲會被打「Inconsistent art style」（酸黃瓜 10-17、相撲猴 11-03）。

**商店圖**
- 縮圖與封面都不含字；FG 層只有主角去背；BG 不可暗。角色改版後縮圖、封面、buy 卡、cut-in、大獎牌上的角色一起重出。

## 5. 收圖當天的驗收順序

順序重要：前面不過就不往下做。全部由 Claude 做，當天做完。

1. **內容**：年齡（66 px 與放大）、著裝、姿勢與體型對需求單的數字、朝向、品牌相似物、70 px 誤讀。不過就整張退、改提示詞重生，不修臉。
2. **畫風**：`scripts/check_style.py` 對 §0 的門檻＋ `art-direction.md` 的 AI 痕跡表（180 px、70 px）。
3. **規格**：尺寸、安全邊、去背色乾淨、每個項目都到齊（對 `assets.ts`）。
4. **角色圖層**（Claude 拆完之後，或收到分層交件時）：
   1. 合成圖對母圖差異為 0：`python3 ~/tools/spine-generator/scripts/check_layer_split.py`（母圖 0 差異、每層一整塊、羽化、近手疊層順序、後層邊緣貼著前層外緣＝沒補畫、微塵）。
   2. **當天就套模板跑全部動作**，每 0.12 秒一格排成表逐張看，重點看肩、肘、頸、髖、膝、腕。不等靜態全過才跑（Dragon Tide R3 靜態過了，一動才看到袖殘留和軀幹破洞）。
   3. `python3 ~/tools/spine-generator/scripts/check_outline_ink.py`：露在外面的邊都有墨線。
   4. 每層單獨放亮底、暗底、**遊戲實際背景色**看。碎點的量法：8 連通＋alpha>0（4 連通＋alpha>127 會把毛尖誤報成碎點）。
   5. MG、FG 同一個部位一起看。
5. **放進遊戲**：真的渲染器、遊戲裡的大小、真的 book。桌機＋直式（390 與 425 寬）、MG／FG、cut-in。換了框或角色就重量角色邊界（不壓盤面、不壓框）。
6. **版本**：遊戲現用的層、交件資料夾、合成圖、Spine images、runtime 裁圖是同一版。有多個交件資料夾時用 md5 比對並寫明哪個是正本，再重建（相撲猴 10-27 差點用舊夾蓋掉修正）。

驗收紀錄寫：看了哪些格、量到什麼數字、哪些沒過、怎麼處理。退件一次列完，附圖與座標。

## 6. Claude 拆層、補底、合成時的規則

- **部件必須是母圖的像素切出來，加上被擋處的補畫。** 不可重新生成整個部件再塞回去（Dragon Tide R1、R2：合成和母圖差 12 萬個像素）。
- **會露出來的地方只能真畫**（開生圖單）。最近色外推、inpaint 只用在永遠不會露出的地方；用在腋下、袖內會變成灰斑或拼貼階梯。
- 補底不用直線、多邊形；不留別的部件的形狀；自動補底要排除墨線（否則墨線被拉成黑帶）。腳和腿不套自動規則（會抹壞鞋子）。
- 兩個部件交界的墨線歸**前面**那層，後層不留。
- 可修改範圍的遮罩由 Claude 畫；驗收時另外不帶遮罩直接比母圖。
- **預覽渲染一律雙線性取樣＋預乘 alpha**，並和遊戲 runtime 同一格比對過一次才可以拿來判定。Dragon Tide 前幾輪的「白虛線」有一部分是預覽工具（BICUBIC＋非預乘）自己畫出來的；Static Shift 的遠側肘「淡虛線」追了兩天，遊戲裡根本看不到。**AA 等級的細線、淡縫，先在遊戲裡截圖確認再處理。**
- 改了圖層就更新來源清單（`source-manifest.json` 之類），不然版本閘門會擋 build；並重寫 full 合成圖。
- 修正要改在模板、參數檔或來源圖，不要直接改編譯出來的 rig JSON（催眠猴改了之後 generator 和它對不上）。

## 7. 什麼時候不要再開一輪生圖

- 碎點、半透明白邊、小洞、掛點、墨線台階：Claude 用程式修。Static Shift 為這些多開了好幾輪。
- 同一個地方第二次沒過：不要再貼一片。改開「整塊重畫」的單，或先查是不是掛點／疊圖順序的問題（Dragon Tide 龍王手腕的縫補了多輪，最後是把袖口改掛到前臂骨才消）。
- 工具的已知誤報先排除：`scan_gaps.py` 會誤報角、髮絲、兩腿之間；匯出工具的「後手腕」警告在叉腰的手臂是誤報。
