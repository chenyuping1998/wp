# Stone 的固定規則（所有遊戲、每一款都適用）

每一條都是 Stone 說過「以後都要這樣」的規則，或同一個錯在兩款以上出現過。新遊戲從第一天就照做；
不要等被退件或被截圖才補。SKILL.md「製程總表」的索引指到這裡，這裡寫出處、做法和驗法。

和遊戲規格衝突時，Stone 當下的指示優先，並回頭更新這份。

## A. 規格、數學、用語

**A1. RTP 每個模式 96.00–96.10%，同一款內主遊戲最低、購買依價格遞增**（10-11、10-15）。例：96.04／96.05／96.06／96.08。全部模式同一個數字是錯的；主遊戲不要放在 96.10。不同遊戲可以用同一組數字。驗：`scripts/preflight.py --upload`（讀 `stakecli compliance`）。做法見 `math-retarget.md`。

**A2. 盤面「A×B」＝ A 列 × B 行**（10-27）。列是橫的 row，行是直的 column（＝輪）。「5×6」＝ 6 輪、每輪 5 格、共 30 格。Hypno Monkey 曾讀反，數學和前端整個重做。收到盤面尺寸先複述「A 列 × B 行（B 輪、每輪 A 格）」再動工。

**A3. 用語**（讀錯過、重跑過最佳化的）：

| Stone 說 | 意思 | 不是 |
|---|---|---|
| odds／賠率 | `game_config.py` 的 paytable 數值 | 命中率、最佳化切片的 hit-rate |
| feature | 這款的招牌機制（擴展 Wild、整盤大框…） | 免費遊戲觸發率 |
| 小圖／小圖騰 | 低分符號（A／K／Q／J） | |
| 大圖／大圖騰 | 高分符號 | |
| 輪 | 一條轉輪（reel／column） | 一次旋轉 |
| 手 | 一次旋轉（spin） | |
| 高均率 | 權重中「贏分高於該模式平均」的佔比 | 命中率 |
| 打包 | stage 到 `upload/<Game>/` 就停 | 壓 zip、上傳 |
| 上傳 | 用 stakecli 推到平台（plan → 同意 → execute；publish 要另一次同意） | 打包 |
| 上線 | 平台核准 | 已 publish |
| 換畫風 | 整個畫面全部換（見 D5） | 只換符號 |
| 摳爹 | Codex（生圖那邊） | |
| 第三版／第四版 UI | 下注列 v3 `MummyBar`／v4 `SplitBar`（見 D2） | |
| 照抄錄／動作完全一樣 | 眼睛看到的動作一樣（見 B10） | 骨頭名稱逐一對應 |

**A4. 自己的機制要自己對 books 驗**：工具鏈只證明 RTP 和內部一致，不知道說明頁答應了玩家什麼。寫二十行腳本走過 books 驗每一句（`review-findings.md`「The maths bug that survived three submissions」）。文案也是對 books 驗，不是對規格（SKILL.md step 6、step 9）。

**A5. 照參考遊戲的規格或節奏時**，整套只用同一款的時間（混用多款會節奏不一致）；只搬規格與節奏，不搬素材；Stake 做不到的機制（跨局狀態、玩家選擇影響結果）直接列進 SPEC 的「做不到」清單。細節在使用者層的 `xinstar-spec` skill。

## B. 角色

**B1. 每款兩隻角色：MG 一隻、FG 一隻，兩個不同的人**（09-28）。同一人換打光不算。換人發生在 FG 開場／結束的轉場底下，不在轉動中、不在中獎時。例外要 Stone 明講（Hard Time 10-20：兩隻同時站盤面左右）。兩隻都不是高分符號的肖像。

**B2. 人物一律一眼就是成年人**（11-10，Engine self-check [217]）。需求單和提示詞不寫「學徒、小徒弟、少女、少年、小～」、不寫 apprentice／girl／boy／young；直接寫年齡（三十歲以上）和成人特徵（鬍子、皺紋、成人臉型與比例），提示詞加 `mature adult, not a child, not a teenager`。收圖第一步先看年齡（66 px 和放大都看）；有疑慮整張退、改角色設定重畫，不修臉。Wild Alchemy 的 H3「學徒」、H4「小徒弟」、FG「人造人少女」就是這樣畫成青少年。`scripts/preflight.py` 會掃需求單用字。

**B3. 先定動作，再定生圖姿勢**（10-27）。寫需求單前列出每隻要做的動作（預設六個＋這款的 reaction、cut-in、開場卡），照 `~/tools/spine-generator/docs/生圖交付規格.md`「第 0 步」把每個動作對姿勢的要求寫在需求單開頭，並確認模板做得到。相撲猴因為先生圖才想動作，生了兩輪才能動。

**B4. 零可見缺陷才算完成**（10-25，全文在 SKILL.md 開頭與 AGENTS.md）。殘影、白邊、碎片、肢體分離、接縫露底、破口、錯誤輪廓任何一個還看得到就不能回報完成、交件或打包。

**B5. 角色面向盤面**（09-27；之後在 Capo 09-28、Dragon Tide 11-09 又各錯一次）。站盤面右邊就面向畫面左邊。三次都錯在「看圖判斷」：
- 需求單寫明朝向。
- 裝進遊戲時查程式有沒有翻面（Capo 系 `Cast.svelte` 的 `flip`／`MIRROR_TO_FACE_BOARD`／`FACES_BOARD_AS_DRAWN`）。
- **不要用原圖、縮圖或裁切圖判斷朝向，也不要用道具或手在哪一邊判斷。** 把角色放進遊戲截圖，原尺寸看**臉（眼睛、鼻子）**朝哪裡。
- 角色出現的每個地方都要看：盤面旁、feature 卡、loading、開場卡、商店圖。

**B6. 角色本體和它演出的一切都不壓盤面**（09-25、10-04）。固定偏移量不行（手臂寬度每隻不同）。每個 `CastFigureMesh` 用 `innerEdge={boardInkRight}` 夾住墨跡範圍加動作餘量；側欄太窄就不畫，不是縮到看不見。**表演也算**：笑聲的「HA!」字、星星、對話、丟出去的道具都要夾在側欄內，用最大尺寸的半寬去夾（Go Banandit `Mascot.svelte` 的 `placement.minX/maxX`）。出拳可以稍微伸進盤面（Hard Time 10-20），待機和本體不行。驗：16:9、16:10、4:3（側欄最窄）各取動作中的格。

**B7. 角色不被背景吃掉**（10-01、10-04）。限色畫風的角色和背景用同一組墨色，人會溶進去。MG、FG 背景各看一次。**修背景，不是在人後面墊東西**：把背景往紙色退（整體約 25%，角色站的那三分之一漸進到約 45%，平滑漸層、沒有邊），角色後面的背景不加網點或紋理。Stone 不要人物後面有淡色面板或聚光圈（「怪怪的白底」）；硬邊墨色位移陰影可以。之後若拿掉描邊或陰影，同一次修改要補回別的分離手段。

**B8. 任何動作都不能有不合理的關節角度**（10-29）。手腕後折、手掌接在前臂中段、手肘反折、換手圖後手腕對不上袖口都算。交件或改動作後，用正式 rig 每 0.12 秒渲染全部動作排成表逐張看；數字和檢查器不能代替。修法與 Spine JSON 的坑：
- bezier `curve` 是**絕對值** `[t1, v1, t2, v2]`：只改 `value` 不改控制點，每段都會盪回舊姿勢（Hypno FG 手臂一圈 85 次反向）。用「每格方向反轉次數」檢查，不是看靜態格。
- 兩節 IK 把手舉過頭會讓手肘翻面、前臂轉一圈。舉手類動作把 IK mix 設 0、直接 key 上臂和前臂：手肘先上、前臂最後伸；放下時手肘先彎。IK 目標 ≤ 約 1.05 倍臂長。

**B9. 修關節不可用直線切輪廓；一隻有問題，兩隻同部位一起查**（10-30）。全文在 SKILL.md 開頭。回報完成前，被點名的那隻和另一隻都要在遊戲裡（桌機＋直式）看過。

**B10.「照抄錄」＝看起來是同一個動作**（09-17）。用抄錄的原始數值，不要「參考後自己詮釋」；本地閘門和抄錄數值衝突時，先懷疑閘門。逐名稱照搬和實際姿勢對不上時，兩種都渲染成並排 GIF 讓 Stone 選。

**B11. 拳套等手部道具疊在頭前面；身體層畫了袖肩時，壓在手臂上的那段不描邊**（10-28、11-07）。前者見 `spine-character`；後者見 `hacksaw-character-motion` 的零缺陷段落（紅藍染色檢查法、`fix_shoulder_ink.py`）。兩條都在需求單第一版就寫。

**B12. feature 演出裡的角色要會動**（10-16）。cut-in、開場／結束卡、升級疊層、獎牌上出現角色時，不能是一張只會滑動的靜態圖。拆層＋照那一拍的時鐘做預備、出手、收勢（SKILL.md step 5 第 6 項）。

**B13. 改動作不能讓角色在遊戲裡變小**（11-09）。側邊角色的縮放由動作包絡寬度決定；出拳加長 → 包絡變寬 → 角色自動縮 6%。改完量包絡寬度並和上一版比遊戲內 scale（`mesh-cast-rig` `references/layered-weighted-mesh.md` 第 10 點）。

---

**B14. 體型寫成數字，全身定稿圖先給 Stone 點頭**（酸黃瓜 10-21「太瘦」、相撲猴 11-07「四肢太細」、Capo 10-04「太細長」，三次都是整組重畫）。四肢與軀幹寬度對頭寬、肩寬腰寬對身高；回來先量。體型或姿勢不對就重生，不用程式角度補超過一輪，不用像素拉寬。

**B15. 動作幅度跟著事件頻率**（Static Shift 10-22，Stone：「FG 人物連線的動態太大」）。每一手都會觸發的反應用腳不離地的小動作；跳躍、大動作只給大獎或進場。待機照 Iron Jaw 的做法：2 秒、軀幹帶動、腳釘在地上。

**B16. MG 和 FG 各有自己的動作**，不整套共用一張動作表，也不沿用來源遊戲的動作檔（Go Banandit 10-04 Poor animations ×2）。

**B17. 換角色或換姿勢時，角色出現的每個地方一起換**：盤面旁、FG 開場與結算卡、loading、buy 卡、cut-in、大獎牌、規則頁、縮圖、封面。漏換發生過六次以上（Hard Time 的開場卡留著退役的角色、相撲猴換粗四肢後商店圖還是舊的）。

## C. 符號與背景

**C1. 每個符號在停輪的盤面上都有自己的待機表演**（10-27，Turf War 5.3 分「too static」）。常駐的小循環＋每 4–8 秒一次的招牌動作，每個符號不同、依格子錯開。1% 的呼吸不算。build 鏈要有 `check_symbol_idle.mjs`（SKILL.md step 4「The symbols live too」）。

**C2. MG、FG 背景都要有自己會動的東西**（10-20），慢慢平移不算。**背景交件要拆物件**（11-09）：每個會動的東西一張 PNG，共用 1920×1080 畫布（火焰、蒸氣、粒子、擺動的物件、遠景月亮…），前端一層一層動。圖層清單先寫進 ART_REQUEST（範本：`new-games/wild-alchemy/SPEC.md` §3.1）。不要再用「從平面底圖裁一塊出來動」的做法。會動的東西不放在盤面後面、不放在角色後面。

**C3. 大圖騰一律有框，和小圖同一款、同樣大小**（10-28），即使參考的原版大圖騰沒框。寫進符號需求單。

**C4. 符號上帶的數值每一階都讀得到**（10-20，Sushi Monkey 銅字在銅盤上＝什麼都看不到）。挑數字圖時就比字色和底色；說明頁列出每一個可能的數值，圖示和盤面上落下的樣子一致（含徽章）。

**C5. 大獎等級對照表要和數學的 winLevel 對上**（11-10，Dragon Tide）。數學用 1–5 級、前端沿用 base 的 10 級對照 → 獎牌顯示錯。換 base 或換數學時查 `setWin.winLevel` 的定義和前端的對照表是同一套，並強制每一級各看一次。

## D. UI 與下注列

**D1. 換皮的 UI 版面照「最近一款已過審的姊妹作」**（10-25，Stone：「不要每次都不一樣」）。下注列底板與圖示比例（整個畫布的圓盤，圖示才夠大）、Buy Bonus 底板幾何、盤面比例與位置、角色擺放規則都一樣，只有皮（配色、圖、字）不同。FG 開場的盤面大小要和 MG 一樣；feature 長出來的列不能讓開場盤面變小或角色變大。驗：過審款與新款同視窗並排截圖（1280×720、390×844），MG、下注列、FG 開場各一張。

**D2. 下注列版本每款都問，不預設**（11-07）。v1 共用 `components-ui-pixi`；v2 GB 系 platformUx；v3 `MummyBar`（連在一起的浮動主控台）；v4 `SplitBar`（左下購買＋選單、底部三塊讀數、右下轉動＋turbo／auto）。**選之前給 Stone 看四個版本的截圖**（催眠猴整套做完 v4、修完範本、打包好，當晚 Stone 看到的參考截圖其實是 v3，整輪改掉）。範本與移植步驟在 yuping 的主線：`git -C wp show origin/main:tools/ui-bar-v4/README.md`（本機 `capo-turf-hardtime` 分支沒有這個資料夾）；修好範本問題的 v3 在 `wp-hypno/apps/HypnoMonkey/src/components/ui/MummyBar.svelte`。移植需要共用鉤子 `uiTheme.customLayout`（各 worktree 不一定有，逐段移植，不整包複製 packages）。**範本本身的已知問題，套用時一併修**：
1. `{#if open}` 的點擊攔截層會蓋在下注列上面 → 自動轉面板和 Spin 點不到。改成常駐、用 `visible`／`eventMode` 切換。
2. turbo 第二段的「2」墨色畫在墨色上 → 看不見。
3. hover 用 `e4e4e4` 灰 → 改主題色（`preflight.py` 會掃）。
4. 餘額不足時按 Spin 沒反應也沒訊息 → 要能按並跳餘額不足提示（[222]）。
5. 選單用 🔊 emoji、選單面板半透明透出後面的東西。
6. v3 貼齊「標準框」底部而不是螢幕底 → 16:10 和手機上浮在半空。
7. 重播時 WIN 疊到 BALANCE 標題上；直式彈出選單太小（約 175 px 寬）。
8. 範本的 ∞ 字型沒有該字、`.selected` 類別會撞到遊戲的全域彈窗樣式。
9. 規則頁的操作說明還是舊圖示和「stop conditions」文字 → 要重做。
10. 每款要有自己題材的購買按鈕圖示（64 px 看得懂）。

**D3. 套用範本或新下注列之後，要看畫面合不合理**（11-09，Stone：「不要有東西歪歪的或是很怪」）。功能測過不夠。實際畫面放大看，尺寸：16:9、16:10、4:3、21:9、5:4、手機橫式、直式、pop-out S；狀態：待機、轉動、中獎、FG、選單／面板開啟、重播。看：字和圖示在底板裡置中對齊、間距一致；控制項沒壓到背景道具或角色（必要時移道具，用量的）；沒有 emoji；半透明面板沒透出殘影；兄弟按鈕隱藏時（FG／重播）沒有留下孤零零的控制項。

**D4. hover 不反灰**（10-01）。共用的半透明白框蓋在彩繪底板上看起來像停用。每款在 `uiTheme.ts` 設 `hoverPlateLight`（題材的暖色）＋ `buyBonusHoverSprite`；淡色紙面底板用 `hoverRimOnly: true`（只亮一圈，不填滿，圖示不會被蓋掉；Sumo 11-03）；hover 圖不能和靜止圖是同一個檔（Sushi 10-06）。驗：每顆按鈕用真滑鼠移上去截圖，靜止和 hover 要看得出差別。細節 SKILL.md step 4。

**D5.「換畫風」＝整個畫面一起換**（10-04）：符號、倍數框、背景、盤面外框、下注列與按鈕底板、Buy Bonus、標題／橫幅／Logo、轉場、特效顏色、兩隻角色。新圖還沒到的部分先用程式做過渡版（例如依明度轉灰階），不要讓舊配色留在畫面上。

**D6. 文字置中是量出來的**（10-16）。pixi 的 `anchor 0.5` 不是視覺中心。`stake-engine-slot/scripts/ui_center_audit.js`，容許 1 px。

## E. 數字與文字

**E1. 數字不壓在插圖上，放在乾淨的紙面／底板上並留邊**（10-29，Stone：「很多款都這樣」）。換圖後，重查每一個相對那張圖定位的數字（`grep -rnE 'InkNumber|max_win|toLocaleString\(|figure:'`）。用圖的 alpha 範圍算出空白處再放；不要用更粗的描邊、光暈或墊一塊底去救。驗：1440×900、390×844、320×568。

**E2. 要數字「更粗、更明顯」時，不可以墨字加墨色粗邊**（10-25）。字腔會被填滿成黑團。用字級、顏色，最多加一圈細的淺色邊（約字級的 0.1）。改完看最暗、最低那一階的實際大小並放大；畫面上任何沒預期的黑塊都要對節點樹查清楚，不能當成是圖。

**E3. 金額一律兩位小數，日圓也是**（10-23，覆蓋官方幣別表的 0 位）；**任何地方都不縮寫 K／M**（10-20）。`numberToCurrencyString` 已經這樣做，不要「修」回去；每個 worktree 確認有這版 `amount.ts`。計數動畫過程中也只顯示兩位（不是四位）。

**E4. 不用 emoji 當圖示、不用系統字型、不用漸層假底板、字不烤進 SVG**：`check_review_tags.py` 會抓。
