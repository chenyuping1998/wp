# Iron Jaw（Xposed Studios，Stake）抄錄：人物動作與轉輪節奏

2026-10-20 使用者給了一支 74 秒的螢幕錄影（Google Drive），這款在平台上是三星，我們的遊戲目前都是二星。
要問的是：人物為什麼動得那麼順、轉輪節奏是怎麼排的。以下數字都是逐格量出來的，
座標是錄影裡 800×450 的遊戲畫布（一格符號高約 64 px），錄影本身是 24 fps。
證據、工具和原始量測在 `/Users/stone/stake-engine/research/drive-3star/`（不進 git），最後一節列出各檔案。

## 1. 畫面配置

- 5×5 盤面放正中，左右各站一個拳擊手，**兩人隔著盤面對峙**（左：金髮紅夾克，右：黑髮藍襯衫，臉上帶傷）。
  兩人都是 MG 的角色，同時也是盤面上的百搭（wild）符號；wild 會長成整輪，整輪上的人像也在做待機動作。
- 背景是一張靜態的夜巷街景，完全不動。一般符號在待機時也不動。
  **畫面上所有的「動」都集中在人物身上**（`stills/heat_idle_8-10.5.jpg`）。

## 2. 人物待機：為什麼看起來那麼順

### 2.1 是 Spine 4.2 骨架（不是影片）

一開始只看錄影，我以為是逐格影片，這個判斷是錯的。直接打開遊戲本體
（`xposed-studios.live.engine.io/iron-jaw/v17/`，跟我們一樣在 Stake Engine 上）
讀它載入的檔案，人物是 `anim/rigs/character/blonde2.json`、`brunet2.json`，**Spine 4.2.43**：

| | 金髮 blonde2 | 黑髮 brunet2 |
|---|---|---|
| 骨頭 | 59 | 45 |
| 部件（slot） | 20 | 17 |
| 網格 | 19 個，全部綁多根骨頭（5605 個頂點值） | 15 個（4090） |
| IK | 2（兩腿，`stretch`，腳釘在地上） | 2 |
| physics | 18（頭髮 7 條、夾克 9 節、褲子 2） | 10（領帶 5 節、頭髮 5 條） |
| transform | 1（夾克跟手臂 20%） | 0 |
| 動畫 | `idle` 2.0 秒、`active` 1.0 秒 | 同 |
| 貼圖 | 一張 1660×3964 KTX2（GPU 壓縮） | 同 |

- 部件切得比我們細：頭、眼睛、身體、夾克前片和後片、上臂、前臂連拳、大腿、小腿、鞋子都分開，再加一條鍊子。
  每個部件都是綁多根骨頭的網格，所以轉頭、推拳時看起來有縮放和透視（量到的頭部 ±5%、拳頭 ±13–15%），不是單純的旋轉。
- **待機只 key 了 9–13 根骨頭，每根 2–4 個 key**，剩下的「順」是 physics 和 IK 自己算出來的：
  - `body`：轉 −0.19° → −2.46°（0.167 秒到，停到 1.167 秒）→ 回來；同時往上 18（1.0 秒最高）→ 回來。
    腳被 IK 釘住，身體一上下，膝蓋就自己彎。
  - `body4`（胸口）：x 5.74 → 6.55 → −3.75 → 5.74，跟 `body` 同一組時間。
  - `head`：轉 7.03° → 0°（1.0 秒）→ 7.03°。
  - 手臂：上臂轉 4–8°、前臂轉 10–13°，到極值的時間依序是身體 0.167、上臂 0.233–0.3、前臂 0.3–0.367 秒，
    **每往外一節就晚 0.067 秒**，拖曳感就是這樣來的。
  - physics：damping 0.85、inertia 0.5，`rotate` 從鏈子根部 0.15 到末端 0.2，越外面甩得越多。
- 錄影裡出拳那幾格的「動態模糊」不是 Spine 做的。比較可能是錄影從 60 fps 轉成 24 fps 時把幾格疊在一起。

### 2.2 循環和時鐘

- 兩個人物的待機都是 **2.00 秒一圈**，正弦擬合 r² 0.97–1.00，接縫誤差 < 1 px，看不到接點。
- 7 秒到 64.7 秒這段（扣掉選單蓋住的時間），待機一圈都沒斷過，**相位一直跟著同一個全域時鐘走**：
  轉輪開始、停輪、贏分都不會讓它重新開始（`measurements/cast_loop_continuity.txt`）。
- 兩個人物用同一個時鐘，但**相位相反**：大約第 0.3 秒時，左邊人物往盤面壓低前傾，右邊人物往後仰起；
  到第 1.3 秒反過來。看起來就像兩個人隔著盤面你進我退在對峙。

### 2.3 振幅：整個身體都在動

追蹤點每圈的擺幅（單位 px，畫布高 450；p2p ≈ 2 × amp）：

| 部位 | 左（金髮） x / y amp | 右（黑髮） x / y amp |
|---|---|---|
| 頭髮頂 | 4.5 / 4.1 | 11.0 / 4.7 |
| 臉 | 5.5 / 7.9 | 7.4 / 4.5 |
| 胸口／肩 | 2.0 / 9.0 | 6.6 / 0.9 |
| 腹部 | 0.0 / 3.7 | 0.0 / 0.6 |
| 後手拳 | 9.8 / 10.3 | 3.6 / 3.2 |
| 前手拳 | 4.7 / 5.1 | 追不穩（形變太大） |
| 皮帶 | 0 / 0 | 0.4 / 1.4 |

- 往上逐漸放大：皮帶是 0，腹部約 1.6%，胸口和頭部到畫布高的 **3.5–4%**，拳頭最大約 4.5%。
  （Stream Time 的點頭是 2%。）
- 左邊人物胸口的上下起伏比頭還大，動作是從肩膀帶出來的，頭只是跟著。右邊人物主要是左右擺，頭髮甩得比臉多（以脖子為支點）。
- 拳頭比頭晚 0.1–0.3 秒到極值，有跟隨的拖曳感。路徑圖：`stills/flow/both_paths.jpg`。
- 波形接近純正弦，二次諧波只佔 10–30%，所以沒有明顯的停頓或卡點。

## 3. 人物反應：出拳

- 觸發條件：**那個人物自己的 wild 長成整輪時，他就出拳**。
  17.17 秒第 2 輪的黑髮 wild 開始往上長，0.04 秒後右邊人物開始連打；64.7 秒兩人的 wild 同時長，兩人一起出拳。
- 右邊人物（17.21–18.04，`gifs/02_R_punch_x4.gif`）：刺拳 → 刺拳 → 勾拳，出手 0.37 秒，
  然後收成高架防守，**停住約 0.2 秒**（17.62–17.79），再回到待機。整段約 0.8 秒。
- 左邊人物（64.67–65.54，`gifs/03_L_punch_x4.gif`）：蓄力 0.3 秒 → 一格整片模糊的直拳（65.00）→
  手臂伸到盤面上**停住約 0.25 秒**（65.08–65.29）→ 回到待機。整段約 0.9 秒。
  拳頭伸進盤面，打中時盤面上跳出「×2」，飛去把倍數翻倍（36× → 72×）：**人物的動作直接送出盤面上的事件**。
- `active`（1.0 秒）的 key：0–0.333 蓄力（頭轉到 26.6°、前臂往後拉到 43°）→ **0.333–0.433 只用 0.1 秒打出去**
  （前臂 43° → −30°、身體往前 42）→ 0.433–0.667 停住 → 0.667–1.0 收回。
- 進出都不會跳格：
  - 進：出拳片段從當下那一格待機畫面接出去，進場那一格的畫面差跟一般動作格一樣大。
  - 出：用大約 **0.17–0.2 秒（4–5 格）交叉淡入**，接回待機，**接在全域時鐘當下的相位**，
    不是從第 0 格重新開始（比對誤差 37 → 25 → 12 → 6.7）。
- 退場的交叉淡入就是 Spine 的動畫混合：`idle` 一直在底下播，`active` 疊在上面，播完混回去。
- 打擊感是靠 0.1 秒的出拳、出手後停住、盤面上的火花和倍數撐起來的，**完全沒有震畫面**（標題和頂部倍數牌位移 < 0.05 px）。

## 4. 轉輪節奏

9 手一般轉動逐格量（`measurements/spin_landings.txt`，`tools/spinland.py`），每一手幾乎一模一樣：

| 階段 | 數值 |
|---|---|
| 起轉前上提 | 0.25 秒；第 1 輪提約 27 px（0.42 格），第 5 輪提約 45 px（0.7 格）；第 1 輪先動，往右一輪輪接著動，**五輪同一格一起往下** |
| 往下加速 | 每格位移 +4 → +24 → 全速，大約 3 格（0.12 秒）就到全速 |
| 上提到第 1 輪停 | 0.63–0.75 秒 |
| 停輪間隔 | **0.23 秒**（0.17–0.26，受 24 fps 取樣影響），換成 60 fps 大約 14 格 |
| 減速 | 停之前 3 格位移 31 → 12 → 2 px，是 ease-out 慢慢煞住，不是全速撞停 |
| 回彈 | 往下超過 **6–8 px（0.10–0.12 格）**，再花 **0.17–0.21 秒**彈回原位 |
| 上提到第 5 輪停 | **1.55 秒**（9 手裡 1.54–1.62） |

- 轉動中的符號是預先畫好模糊的版本（看得到直條紋），不是即時加模糊。
- 這 9 手都沒有吊輪（anticipation），所以節奏完全固定。只有 27.62 那手第 5 輪比第 4 輪只晚 0.08 秒停，回彈 16 px，原因不明。

## 5. 特色玩法的節奏（買 Juicer Spins 那手，55–70 秒）

- 轉盤：從符號位置放大成轉盤。第一個轉盤轉約 3.6 秒（57.1–60.75），結果「+5×」飛到頂部倍數牌（1× → 6×），
  轉盤縮回符號。第二個約 1.5 秒（×3 → 18×），第三個約 0.7 秒（×2 → 36×）。**同一個演出重複時，一次比一次快。**
- 接著 wild 長滿整輪、人物出拳（§3），倍數翻倍，贏分一個個疊上去。
- 大獎分級（67.0–69.9，共約 2.9 秒）：HIT ME → BEATDOWN → KNOCKOUT → MAYHEM，每一級約 0.6–0.8 秒，
  級跟級之間用白色碎玻璃轉場，每一級都有自己的一張全身插圖，數字一路往上跳。

## 6. 跟我們目前做法的差距（對照 wp）

1. **人物骨架的密度**：我們的香蕉猴 Spine（`hacksaw-character-motion/gobananas_monkey`）是 24 根骨頭、13 個部件、
   4 個綁骨網格、7 個 physics、沒有 IK。Iron Jaw 是 45–59 根骨頭、17–20 個部件、15–19 個綁骨網格、10–18 個 physics、
   兩腿 IK 釘腳。播放端我們已經有 `@esotericsoftware/spine-pixi-v8` 4.2.74，支援 physics，差的是部件切法和骨架生成。
2. **兩個人物共用一個時鐘、相位相反**，隔著盤面你進我退。（我們的 MG/FG 角色分開出場，要抄得先讓兩人同時在畫面上。）
3. **反應片段要跟盤面事件綁在一起**：誰的 wild 落地誰就出拳。片段 0.8–0.9 秒，出手後停 0.2–0.25 秒，
   0.17–0.2 秒交叉淡入接回待機的全域相位，不要重新開始循環。
   （注意：他們的拳頭會伸進盤面，跟我們「人物不壓盤面」的規則衝突，抄的時候要先決定。）
4. **轉輪停輪**：Hard Time 現在是全速撞停（`reelSpinSpeedBeforeBounce` 4），然後彈 0.3 格（`reelBounceSizeMulti` 0.3，回彈約 236 ms）。
   他們是 ease-out 煞停，只彈 0.1 格、0.17–0.2 秒。停輪間隔他們 0.23 秒，我們約 0.28 秒。
   我們的起轉用 backIn，已經有上提，但五輪不是同一格一起往下。
5. **同一個演出重複時要越來越快**（轉盤 3.6 → 1.5 → 0.7 秒）。
