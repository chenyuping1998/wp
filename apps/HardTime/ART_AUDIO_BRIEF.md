# Hard Time — 美術與音效需求單

配合 [SPEC.md](SPEC.md)。本檔是 Hard Time **唯一**的美術與音效需求單。

scaffold 時一併複製進來的 `ART_BRIEF.md` / `ART_STATUS.md` 是**母體 Capo Nostra 的**（與 `wp/apps/CapoNostra/` 裡的原件逐位元組相同、零處提到 Hard Time），已於 2026-09-15 從本 app 刪除；原件仍在 CapoNostra。src 註解裡「ART_BRIEF.md §N」的引用已改指向本檔對應章節。

這份不是資產清單，是**規則**。清單從規則掉出來。理由很直接：第二、第三輪重新生成
的圖，需要的是規則，不是「再畫一張」。

## 0. 保留色（先讀這條，它約束後面每一條）

**探照燈的光色是本作唯一的訊號色，任何其他地方一律不准用。**

Capo Nostra 把警報紅鎖給 Tommy Gun 專用，後來在免費遊戲層級名上發現同一個紅，
被判定為「第二個東西穿了警報色」而必須改掉——因為那會破壞「紅色＝Tommy Gun」
這個唯一讀法。本作繼承同一條紀律：探照燈是整台機器唯一的機制，它的光色必須
一看就知道是它。

建議：冷白偏青的探照燈光（例如 `#DCE8F0` 光芯、`#8FB4C8` 光暈）。監獄場景其餘
部分走水泥灰、鏽鐵、卡其囚服的暖濁色，讓冷光在其中唯一地「亮」起來。

## 1. 角色

**本作是一個人，不是兩個。**

現況是 `CastFigure.svelte` 的 `CAST_NATIVE = { guy: 441×1100, girl: 473×1100 }`
—— 這是 Hot Miami 的「男女兩人分別代表 base / feature」設定，Capo Nostra 換皮時
沒有清掉，又原封不動被複製進本作。本作的敘事是**同一個人從西裝老大變成囚犯**，
不存在第二個角色的邏輯位置。

需求：

- **一位主角**，即 Capo Nostra 那位老大，現在穿囚服。**沿用同一個身形比例**
  （441×1100 那組）——這不是偷懶，是因為那個剪影的手臂留白已經通過 mesh 綁定
  驗證，重畫一個新姿勢等於把 `mesh-cast-rig` 的驗證重做一次。
  > **更正（2026-09-17）**：這句的前提是錯的。441×1100 是平面 sprite 的尺寸，mesh rig
  > 是 512×1024、綁在 Hot Miami 另一張圖上，從來沒有「驗證過這個剪影」。囚犯畫得比那張寬，
  > 手臂位置不同，rig 沒重綁，骨頭落在衣服上。已重綁，見 HANDOFF.md §3.1。
  > 下一次重畫：手與大腿之間至少留 **24px**（一格 32px）——現在只有 5–10px，
  > 手臂擺動的剪力無處可放，是這張圖手臂只能動 4.5 度的原因。
- **手臂與軀幹之間必須留可見的空隙**。`mesh-cast-rig` 的權重需要一條能分辨
  「手臂」和「軀幹」的界線；手臂貼身的姿勢在動畫尺度下會讓手掌視覺上陷進衣服裡。
  這條要在生成時就講，不要等綁完才發現。
- 服裝細節：灰色或卡其囚服、胸口號碼布標、袖口可見的手銬磨痕。**不要畫實際暴力、
  不要畫傷口**——核准指引第 44 條「資產與圖像不得含冒犯或不當內容」。

## 2. 符號

### 2.1 靠剪影和材質區分，不要靠色相

本作的調色盤是刻意收窄的（水泥灰／鏽鐵／卡其），這代表**五個高階符號會落在同一個
色系裡**。生成式繪圖在這種情況下的預設行為是用顏色區分，結果就是調色盤一統一，
五個符號立刻變得分不出來。這條必須明寫在每一輪提示詞裡。

| 代號 | 物件 | 賠付 5/4/3 | 剪影記憶點 |
|---|---|---|---|
| H1 | 獄警鑰匙串 | 250 / 60 / 25 | 一圈鑰匙，外輪廓破碎、有很多尖角 |
| H2 | 手銬 | 125 / 36 / 12 | 兩個閉合圓環，最規則的幾何形 |
| H3 | 私藏鐵盒 | 32 / 12 / 2.5 | 方正的盒，唯一的矩形實體 |
| H4 | 錫杯與湯匙 | 18 / 6 / 1.2 | 圓柱＋斜插的細長桿 |
| H5 | 囚服號碼布標 | 6 / 2.4 / 0.6 | 扁平矩形布片，邊緣毛躁 |
| L1–L4 | 黑桃／紅心／方塊／梅花 | 1.2 / 0.6 / 0.25 | **保留現有花色**——囚犯打牌，主題上完全成立，省一整組美術 |
| W | 囚帽 | 5 連線 250 | — |
| SW | **探照燈** | 不出現在賠付表 | 見 §3，它從不以自己的身分被結算 |

賠付數字取自 `game_config.py` 的 `self.paytable`，已較 Capo Nostra 整體下調約 38%。

### 2.2 可量化的視覺重量規則

「看起來高階一點」不是需求。需求是：

> **低階符號實測的亮度／亮區佔比，不得超過任何高階符號的最小值。**

做法：在交付解析度下量每個符號的可見像素覆蓋率與亮區百分比。若某個低階符號的
數字贏過所有高階符號，視覺階層就是反的，不管單看好不好看。**某一版通過之後，把
實測數字寫回這份文件**，讓後續重新生成有目標可對，而不是只有一句規則。

2026-09-14 最終輸出實測（底板 `RGB(34,35,33)`，由
`design/check_symbol_weight.py` 於正式 build 自動重驗）：

| 符號 | 覆蓋率 | 亮區 | 對比 |
|---|---:|---:|---:|
| H1 | 34.9% | 1.0% | 6.97 |
| H2 | 28.5% | 1.7% | 8.76 |
| H3 | 41.6% | 1.3% | 6.75 |
| H4 | 30.1% | 0.8% | 7.32 |
| H5 | 33.0% | 0.1% | 6.96 |
| L1 | 5.9% | 0.0% | 5.58 |
| L2 | 6.3% | 0.0% | 5.08 |
| L3 | 4.8% | 0.0% | 5.08 |
| L4 | 6.8% | 0.0% | 5.58 |

低階覆蓋率最高 6.8%，低於高階最低 28.5%；低階亮區最高 0.0%，低於高階最低
0.1%。視覺重量規則通過。

## 3. 探照燈（本作唯一的機制，美術份量最重的一項）

機制回顧（完整版見 SPEC.md）：光束**只往下照**，從落點那一格照到該輪最底；照到的
格子變成 Wild 並各自帶一個倍率；連線穿過幾個亮格就加幾次倍率；**同一輪**（＝同一
直行）再落一盞燈時，重疊到的格子倍率 ×2。

需要的資產與規格：

- **燈具本體（SW 符號）**：塔上的探照燈，燈頭朝下。它會停在格子上被看見一拍，
  然後才掃下去——所以它要能單獨當一個符號讀。
- **光束本體**：從落點往下的梯形光柱，**必須支援 1 / 2 / 3 / 4 格四種長度**
  （落在最底排只照 1 格，落在最上排照滿 4 格）。不要交一張固定長度的圖。
- **光束不透明度要給數字，不要說「淡一點」**。光束疊在符號上面，太實就把符號蓋掉。
  目標：**光芯峰值不透明度 60–70%，往外緣遞減到接近全透明**。Capo Nostra 有過
  「交來的框是軟化前的版本」這種事故，靠讀 diff 抓不到，只能靠量。
- **倍率數字的底板**：每個亮格各自帶一個數字（不是一盞燈一個數字）。同一條光束裡
  的格子可能帶**不同**的數字（翻倍只作用在重疊格），所以底板必須是**逐格**的，
  不能設計成「整條光束共用一個大數字」。
- **翻倍的視覺**：`searchlight` 事件的每個 cell 帶 `doubled: true/false`。這兩件事
  在盤面上是同一個數字、但完全不同的事件——「這格剛亮起來是 8×」跟「這格本來就是
  8×，第二道光把它推到 16×」。美術要給翻倍一個專屬的強調（建議：光芯瞬間過曝＋
  數字彈跳），否則前端只能靠猜。

## 5. 轉場

**不准用牢門關上。**

母體的轉場是金庫門關上；牢門關上是同一個母題換皮，skill 明文禁止（「Re-derive the
beat from the new theme, don't just recolour the old one's asset」）。

本作轉場：**全區斷電 → 紅色警報燈亮起**。

- 機制上要完成的事：遮住盤面切換的瞬間、讀起來是升級。
- 視覺上：畫面先整個沉入黑（0.25 秒），紅色旋轉警報燈從兩側掃入，光束掃過時露出
  新場景。
- **警報燈的紅不得與探照燈的冷白光混用**（見 §0）。這是兩個不同的東西：探照燈是
  玩家的獎勵，警報是場景的狀態。

## 6. UI 外框

- **Buy Bonus 有兩個不同的資產，很容易只做一個。**
  1. 彈窗裡的卡片外框（需要 9-slice，要標出四邊 border inset）
  2. **常駐在下注列的 Buy Bonus 按鈕底板**（單張不拉伸圖）

  Capo Nostra 的需求單從第一天就涵蓋了彈窗卡片，下注列按鈕的底板卻是好幾週後才
  被要求補上。這次一次講完。

- **已確認：本作的兩個 UI skin 都有宣告 `buyBonus: 'hmUiBuyBonus'`**
  （`src/game/uiTheme.ts:303` 與 `:504`），所以新圖丟進去會正常顯示，不會踩到
  「platform chrome skin 把 sprite slot 清空導致渲染成灰色方塊」那個坑。這是查過
  的，不是假設。

- **沒有專屬美術的共用彈窗（設定、一般提示）仍然需要新主題的色票。**
  這是程式端的工作，但寫在這裡，免得被當成「不是美術的事」而漏掉。共用 UI 套件
  預設會沿用上一個動過它的遊戲的調色盤。

## 7. 字體稽核

繪製字樣與執行期文字必須語言一致。現況 `src/app.html` 已載入 Titan One / Cinzel /
Orbitron / Saira——**這是三個遊戲累積下來的字體庫，不是本作的選擇**。

- 標題／層級名／大獎橫幅（畫在圖上的字）：建議**帶壓印感的窄體無襯線大寫**，像
  沖壓在鐵牌上的字。監獄的字是被壓出來的，不是被刻出來的（那是 Capo Nostra 的
  石刻 Art Deco，不要沿用）。
- 執行期數字（下注列、賠付表、HUD）：**不跟隨標題字體**。標題字在下注列尺寸會輸
  給可讀性。維持窄體、等寬數字。
- 交付前逐項列出：每個繪製字樣資產用什麼字 / 每個執行期文字表面用什麼字 /
  任何還在吃共用元件內建字體的地方（那通常是母體或樣板的選擇，不是本作的）。

## 8. 音效

### 8.1 現況

`static/assets/audio/sounds.json` 有 52 個 key，整包是母體的。其中
`sfx_multiplier_landing` / `_combine_a` / `_combine_b` / `_explosion_a|b|c` /
`_update` / `_reset` 這一整組是**為金框設計的**——金框會落下、會合併、會爆開。
本作沒有金框，這組聲音對不上任何事件。

`static/assets/audio/capo/`（11MB，含 Tommy Gun 的 `sw_gunfire.wav`）已於 2026-09-15 刪除。
它曾經隨出貨包一起送出——打包 gate 只掃 `assets/sprites`，是列 zip 內容才抓到的；
gate 現已擴大到整個 `assets/`。

### 8.2 新事件對應的聲音需求

書事件只有三個：`searchlight`、`updateLights`、`bonusTier`。音效要照這個對，
不是照舊的金框組硬套。

| 新音效 | 觸發點 | 設計要求 |
|---|---|---|
| `sfx_light_land` | 探照燈符號停在盤面上 | 金屬燈具卡榫定位的「喀」聲，短、乾 |
| `sfx_light_sweep` | 光束往下掃 | **音長必須隨光束長度變化**——照 1 格和照 4 格不能同一個聲音。建議做成可裁切的掃頻，或做 4 個變體 |
| `sfx_light_double` | `doubled: true` 的格子 | 與 `sfx_light_sweep` **明確不同**的一擊。這是本作最重要的音效差異：玩家必須用耳朵就能分辨「新亮」和「翻倍」 |
| `sfx_lights_carry` | `updateLights`（免費遊戲每手開頭） | 低頻的持續嗡鳴，提醒「這些燈還在」。要能疊很多層而不吵 |
| `jng_tier_lockdown/riot/breakout` | `bonusTier` | 三段遞進，共用主題動機，配器逐層加厚 |
| `sfx_alarm_transition` | 轉場（§5） | 警報器起音 + 斷電的低頻墜落 |

### 8.3 保留與汰除

- **保留**：`bgm_*`、`sfx_reel_stop_1..5`、`sfx_scatter_*`、`sfx_winlevel_*`、
  `sfx_btn_*`、`sfx_anticipation*` —— 這些綁的是通用轉輪與贏分階層，與機制無關。
- **汰除**：整組 `sfx_multiplier_*`（金框專用），`tumble_win_1..5`（本作不是
  tumble 機制，母體也沒在用）。
- **重做**：`bgm_main` / `bgm_freespin` 使用低調的監獄爵士／潛行配樂；必須有可辨識但
  不搶戲的和弦、短旋律與輕節奏，避免以持續低頻嗡鳴或寬頻噪聲作為主體（會像冷氣聲）。
  Base 採較疏的 D minor 90 BPM 循環；Free Spin 採同主題 96 BPM 變奏並稍加旋律層次。

### 8.4 一條紀律

Capo Nostra 送審被打回的兩個理由之一就是**音效薄弱**（5.3/9，2026-09-04）。
Turf War 的 win audio 到現在還是 PENDING。音效不是最後補的東西，它跟美術同期。
