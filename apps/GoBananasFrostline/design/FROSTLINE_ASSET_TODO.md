### 驗收時發現的一件事

交付說明寫「圖像使用 OpenAI 內建 image generation **逐張生成**」。這正是
`gb-spine-and-art` skill 警告的做法（"Generate the whole set in one pass"），
而量測結果也確實呈現出來了——**底板亮度分成兩群**：

```
h1–h4 / s / p   底板 (27,39,52) … (52,63,75)    暗、偏藍、有冰晶紋理
l1–l5 / x       底板 (72,81,91) … (89,98,108)   亮、偏灰、素面
```

高低賠**本來就該有階層線索**（本規格第 20 行要求 `h`/`s` 加冰藍內斜角、`l` 維持
素鋼），所以這個差異方向是對的，在 118px 實際尺寸下也讀得出是「高賠冰、低賠石」。
**但幅度比規格設想的大**（底板值差約兩倍，邊框粗細也不同），而規格明確要求
「邊框粗細所有符號一致」，因為盤面不畫格線、符號邊框就是格線。

**沒有做事後校色**，這是刻意的：skill 明確說 "Plate colour belongs in the prompt,
not in a correction pass"。要收斂的話應該是**把 l 系列連同 h 系列一次重生**，
並在提示詞裡把底板值寫死。

# 一、盤面圖案（12 張，W 家族除外）

## 交付格式（沿用 `GEN2_ART_SPEC.md` 第 1 節，不要改）

| 項目 | 規格 |
|---|---|
| 來源尺寸 | **1024×1024**（最低 512×512）。遊戲內是 256×256，來源大才有銳利度餘裕 |
| 長寬比 | **正方形**。非正方會被補邊，邊框粗細就不一致了 |
| 格式 | PNG，**不透明**（整塊底板，不留透明區）|
| 色彩空間 | sRGB |
| 檔名 | 全小寫，見下表 |

## 底板規則（12 張共用，這節決定盤面整不整齊）

底板是把 25 格串成一面牆的東西，**必須高度一致**。

- **深板岩藍金屬**，邊框取樣色 `#3b434d`–`#4e5762`
  （對應 `src/game/palette.ts` 的 `ICE_PLATE`）
- **絕對不要做成白色或淺色。** 這是整份規格最容易做錯的一條：極地主題最直覺的
  做法是白底板，但識別色全靠壓在暗底上才分得開，白底一上去五個顏色同時失去對比。
  **雪白留給背景和人物，底板走暗色。**
- 四角各一顆鉚釘，邊緣一圈內凹陰影
- **邊框粗細所有符號一致**（盤面已經不畫格線，符號的邊框就是格線）
- **階層線索**：`h1`–`h4` 與 `s` 的底板加一圈**冰藍內斜角**；`l1`–`l5` 維持素鋼。
  讓玩家不靠顏色也能分出高低賠

## 硬性對比規則

- 主體與底板的**平均明度差 ≥ 30%**（約 8% 男性有色覺辨識障礙，只靠色相會失效）
- **瞇眼測試**：縮到 64px 瞇眼看，兩張高賠符號的色塊分佈長得像就是失敗
- `l1`–`l5` 之間不需要明度差（本來就該像），但**每個字形的外輪廓要夠不同**

## 共通打光

- **左上方單一冷光**，右下陰影，全套一致
- 整體偏暗、低飽和的極地軍事風；**只有主體的識別色可以高飽和**
- 金屬鏽蝕改成**結霜與冰殼**：邊角掛細霜、表面有薄冰的反光
- 避免：乾淨塑膠感、卡通描邊、外發光、彩虹色散
- 主體置中，佔畫面約 **70%**，不要頂到邊框

### ⚠️ `h4` 為什麼一定要換色

一代的 `h4` 是**青藍**指北針，那在**橄欖綠底板**上成立。底板換成板岩藍之後，
青藍主體壓在藍灰底上會糊成一團。改成**暖銅色**的手持暖爐或煤油燈，既解決撞色，
在極地主題裡也比指北針更有敘事。

### 其他注意

- **`h3` 箱側不可出現任何金額或博弈字眼**（Stake social 限制字表）。
  文字用 `SUPPLY` 之類或純圖樣。
- **`s` 必須是全盤唯一的金色物件**。`h4` 改暖銅之後要注意兩者距離，
  暖銅要明顯比金暗、比金濁。
- 這 12 張畫完之後，`design/generate_mode_cards.mjs` 會自動把它們合成進買轉卡，
  所以買轉卡不需要另外畫。

### 下一次動音效之前，先解決這件事

兩版都沒有留下「哪裡不對」的紀錄，所以第三版一樣是猜。**在做之前先取得具體回饋**，
至少要能回答下面其中一項（這份清單第一版就寫了，但沒有被填答過）：

- **太吵／太小聲** → 調 `Sound.svelte` 的 `volume` 就好，不必重生成
- **不像冰，像白噪音／嘶聲** → 分音結構問題，要加更多非諧和共振峰、拉長 ring
- **太合成、太電子** → 要加不規則性：微小音高漂移、每次觸發的細微變化
- **和畫面對不上** → 時間點問題，改 `ExpandingWilds.svelte` 的觸發時機，不是音檔
- **整體方向就不要** → 例如根本不想要冰的音色，想維持叢林打擊樂

**沒有這個答案就不要再生第三版。**

### 第一版為什麼會過關又不行 —— 這條仍然成立

### 第一版為什麼會過關又不行 —— 這條比清單本身重要

第一版是**量測驗收**的：峰值、分段響度、分段頻譜重心，三個都符合設計意圖
（creep 往上掃 3651→6358Hz、freeze 往下掃 4998→2012Hz、crack 有真正的暫態）。
數字全對，聲音不行。

**量測能證明「形狀」對，不能證明「音色」對。** 包絡走向、頻譜重心移動方向、
暫態銳利度——這些都是骨架；一個合成音可以骨架完全正確而聽起來仍然像廉價的
白噪音玩具。這件事沒有離線的替代方案：**這批必須有人真的聽過才算數。**

（同樣的限制也適用於下面每一個待做音效。量測用來擋明顯的錯——掃反方向、
包絡是平的、削波——不能用來取代試聽。）

### 重做前要先問清楚的

第一版的具體問題還沒有紀錄。開工前先確認是哪一類，否則第二版只是換一組亂猜的參數：

- **太吵／太小聲** → 調 `Sound.svelte` 的 `volume` 就好，不必重生成
- **不像冰，像白噪音／嘶聲** → 分音結構的問題，要加更多非諧和共振峰、拉長 ring
- **太合成、太電子** → 要加入不規則性：微小的音高漂移、每次觸發的細微變化
- **和畫面對不上** → 時間點問題，改 `ExpandingWilds.svelte` 的觸發時機，不是音檔

## 合成手法備忘（寫給下一個做這件事的人）

兩件事決定像不像冰，細節見 `design/generate_audio_frost.mjs` 檔頭：

1. **噪音 + 非諧和高頻分音。** 諧和分音聽起來會像三角鐵。
2. **掃頻要逐樣本算**（state-variable filter），因為截止頻率必須在單一音效**內部**
   移動——結霜往上掃、鋪底往下掃。

**量測只是第一道關**：峰值、分段響度、分段頻譜重心，用來擋掉掃反方向、包絡是平的、
削波這類明顯錯誤。第一版三個音效全部通過這關，**然後還是被判定要重做**——所以量測
之後一定要有人試聽，那一步不能省。
