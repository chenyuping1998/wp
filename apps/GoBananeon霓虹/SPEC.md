## 0. 這份規格要先講的一件事

Delta 的機制是**切開**——砍刀把一格切成兩格，ways 翻倍。

Boomana 的機制是**合併**——炸藥炸開岩層，露出一塊佔滿多格的巨大礦體。

同一個軸的反方向。這不是換皮，玩家會認得是同一個系列的新想法。

被否決的第一版設計（記錄在此避免重走）：「炸藥讓那一輪之後掉高分符號」。它的問題是**改變的是機率分布，不是玩家正在看的盤面**——玩家看不見機率，沒有那個「一刻」。而且它結構上和 Delta 完全同形（某輪變強、免費遊戲累積），等於換皮。

## 1. 基本規格

| 項目 | 值 | 說明 |
|---|---|---|
| 盤面 | 4 列 × 5 輪 | 沿用 Delta。**不要加列**，理由見 §5 |
| 基礎 ways | 1,024 | 4^5 |
| 賠付方式 | ways，左到右，第 1 輪起算 | |
| RTP | 0.96 | 五個模式一致 |
| Max win | 10,000x（hold and spin 1,000x） | |
| 起賠 | 3 連 | |

符號沿用 Delta 的分級：H1–H4、L1–L5、W（wild）、S（scatter）、**B（炸藥，取代 M）**、P（金幣，hold and spin 用）、X（空格）。

## 2. 核心機制：炸藥與礦體

### 主遊戲

轉輪停下 → 盤面上若有炸藥 **B** → 引爆 → 以它為中心炸開 **2×2 礦體**：那四格全部變成**同一個高分符號**，並且視覺上合併成一塊。

- 礦體的符號由數學指定（權重表決定是 H1/H2/H3/H4 哪一個）
- **炸藥本身不賠付，也不會被覆蓋**
- **礦體不會蓋到 Scatter** — 否則觸發率會被機制本身扭曲，數學會極難調。這條和 Delta 的「砍刀不切 Scatter」是同一種保護
- 每輪最多一顆炸藥（沿用 Delta `make_reels.py` 的 `space_machetes` 間隔邏輯，改名即可）
- 主遊戲**不累積**：一顆炸藥、炸一次、本轉有效

### 免費遊戲：礦體會長大

Delta 最成功的部分是分割會累積、盤面隨回合肉眼可見地變強。同樣的曲線，換一套語彙：

| 第幾次引爆 | 礦體尺寸 |
|---|---|
| 1 | 2×2 |
| 2 | 3×2 |
| 3 | 3×3 |
| 4 | 4×3 |
| 5+ | 4×4 |

**這個升級是用眼睛看的，不用讀說明。**

### 為什麼礦體在 ways 遊戲裡是大獎引擎

一個 2×2 礦體跨在第 2、3 輪：那兩輪各貢獻 2 格同符號，`×2×2`，而且**連續兩輪已經先連好**——三連的門檻只差一輪。3×3 光是自己就鎖死 27 ways。

這正是把波動放在對的地方：礦體只在少數轉出現，不抬高平常盤面的 `E[ways]`，所以不吃 §5 的下限稅。

## 3. 投注模式

| 模式 | 成本 | 內容 |
|---|---|---|
| base | 1x | 主遊戲 |

| bonus100 | 100x | 免費遊戲，開場已有 **2×2** 礦體 |

各檔**只差一件事，而且那件事看得見**——卡面就畫 1 塊由小到大的礦體。沿用 Delta 的 `generate_mode_cards.mjs`，把砍刀欄換成礦體。

Scatter 觸發：3/4/5 個 → 8/10/12 轉（沿用 Delta，數學跑完可再調）。

## 4. 前端實作要點

### 關鍵決定：礦體在轉輪停下後才揭示

Delta 的砍刀只影響**一輪**，所以能活在單一轉輪容器裡。**2×2 礦體跨兩輪，放不進任何一個轉輪容器。**

解法是一個劇情上剛好更好的決定：**轉輪停 → 引爆 → 岩層炸開 → 礦體露出**。

這樣礦體永遠不需要跟著轉，跨輪不再是問題——它變成畫在盤面上方的疊層物件，用盤面座標定位。專案裡已經有一模一樣的東西：`StickyPrizes.svelte` 就是把金幣黏在盤面上畫在轉輪之上。**抄那個結構。**

而且這比「礦體轉進來」的敘事更對：你是炸開岩石**發現**它。

### 難度評估（相對 Delta 的砍刀）

| 部分 | 難度 | 說明 |
|---|---|---|
| 爆炸特效 | 更簡單 | `FxBurst`、`ImpactDust`、`sfx_multiplier_explosion_a/b/c` 都現成 |
| 符號繪製 | 更簡單 | 畫一次放大；Delta 要畫兩次半寬且只有左半能帶 `oncomplete` |
| 跨輪佈局 | 新問題 | 用「停轉後揭示 + 疊層」化解，有 `StickyPrizes` 範本 |
| 得分演出 | 稍難 | `WinWays` 現在逐格框選，礦體要當**一個**物件框，否則四個框疊在一起 |
| 狀態同步 | 一樣難 | 見下 |

### 會咬人的是狀態，不是動畫

Delta 的分割演出修了三次以上，**沒有一次是動畫本身的問題**：

- 上一局得分演出蓋到下一轉（真因是閒置重播迴圈在預轉期間醒來，`stopWinLineReplay` 必須在回合開始時呼叫，不是在 `playBet`）
- 已經作用過的輪再次觸發，狀態畫錯
- turbo 變體
- 續玩／重播要能從書本快照重建

礦體會遇到同一組問題。**這些現在都有現成答案**，抄模式比重踩便宜。

### 已決定的介面

`reveal` 事件帶：

```ts
megaBlocks: [{ reel, row, w, h, symbol }]
```

**每次都帶完整清單，不是增量。** 這是 Delta 的 `splitReels` 事件帶 `allReels` 的同樣理由——續玩快照只讀最後一個事件就要能重建整個盤面。這個欄位形狀在寫數學前就定，可省一次重構。

## 5. 數學上必須先知道的四件事

這四條全部是這一季在 Delta 上實際撞出來的。

**5.1 賠付表必須整齊落在 0.10 的格線上**

RGS 檢查是 `payout >= 10` 且 `payout % 10 == 0`。Delta 第一版把賠付做得很細（0.04、0.06、0.14）想壓低波動，結果兩萬本書有 **11,941 本不合格**，整張表重做。ways 的賠付是 `paytable × ways`，ways 是整數，所以**整張表都在 0.10 格線上就自動滿足**。

**5.2 不要加列**

ways 的賠付隨盤面尺寸相乘，所以 RTP 的**下限**由 `E[每轉 ways]` 決定，與命中率無關。實測：

| 盤面 | E[ways] | 合法最低賠付表吃掉的 RTP | 剩餘設計空間 |
|---|---|---|---|
| 5×5 | 3.96 | 79.1% | 16.9% |
| 4×5 | 1.48 | 26.9% | **69.1%** |

「往下挖、盤面長高」聽起來最貼題，但在 ways 遊戲裡是死路。**礦體機制正好繞開這件事**：盤面尺寸不變，變的是格子的內容。

**5.3 先量盤面自然產出什麼，再定目標值**

最佳化器只能重新加權既有的書，不能無中生有。Delta 一度把命中率設成 77%，而轉輪帶自然只有 38.6%——硬做到了，代價是 72% 的回合賠 0.01x–1x，「名義中獎、實際虧錢」。目標值離自然值太遠就是在偽造手感。

同理，`>=1x` 的比例：Delta 自然盤面是 16.65%，發布表被壓到 5.26%（因為 base criteria 只分到 0.675 RTP，而自然平均是 0.794，最佳化器只能砍最貴的那一段）。最後調到 8.53%。**Boomana 要在跑完第一輪後量同樣的兩個數字。**

**5.4 SDK 的 ways 漏洞**

`src/calculations/ways.py` 原本只用第一輪實際出現的符號名稱當候選，所以**第一輪的 wild 無法起始得分**——wild 反而讓盤面賠得比普通符號少，整輪 wild 賠零。這一季修了，用 `wild_starts_win` 開關，**預設關閉**。

**Boomana 必須明確開啟：**

```python
Ways.get_ways_data(self.config, self.board,
                   multiplier_strategy="symbol", wild_starts_win=True)
```

Delta 的 `game_executables.py` 已經是這樣，複製過來時檢查沒被改掉。

## 8. 現行機制（取代 §2）

礦體方案在實作評估時被否決：2×2 跨兩輪，放不進任何一個轉輪容器，需要一整套疊層繪製系統。

**現行：炸藥填滿整輪。**

轉輪停下 → 炸藥引爆 → **那一輪每一格都變成同一個符號**，取「該輪原本最高分的符號」。

緊張感發生在爆炸**之前**：炸藥落下的那一刻，玩家去看那一輪上面有什麼，因為那決定結果。

### 階梯（免費遊戲）

炸藥會**累積**，每過一個門檻，爆炸就多覆蓋一輪：

| 累積炸藥 | 爆炸寬度 |
|---|---|
| 0 | 1 輪 |
| 2 | 2 輪 |
| 4 | 3 輪 |
| 7 | 4 輪 |
| 10 | **5 輪 = 全盤同圖，1,024 ways** |

門檻是量出來的，不是憑感覺：2/4/7/10 給出「到 L2 72%、L3 24%、L4 1.2%」，是唯一一組讓階梯**真的會爬**的設定。更陡的 3/7/12/18 平均值更接近三代，但階梯幾乎不動，儀表板會變成從不改變的裝飾。

### 這是一款高起伏遊戲，這是決定不是漂移

量過所有設定，**中位數都落在 5x 附近**，無法重現三代的 mean 40x / median 29.6x。原因是結構性的：三代的分割每轉累積一點，價值攤平；爆炸是全有全無，價值集中在罕見的寬爆炸。

**但主遊戲仍然是三代的手感**：每轉 0.800（三代 0.794）、命中率 36.1%（三代 38.6%）。玩家絕大部分時間待的地方沒變。

### 已發布數值

| 模式 | RTP | 命中率 | Max win |
|---|---|---|---|
| base | 0.9600 | 36.33% | 10,000x |
| holdandspin | 0.9600 | 52.68% | 1,000x |
| bonus100 / 200 / 300 | 0.9600 | 100% | 10,000x |

主遊戲賠付分布：不中 63.7%、<1x 29.6%、1–5x 3.95%、5–20x 1.99%、20–100x 0.67%、**100x+ 0.11%**。`>=1x` 為 6.73%。

觸發率由 scatter 密度降到 **1/441**（三代 1/144）——特色遊戲值 ~116x，用舊觸發率會吃掉 0.426 的 RTP 而預算只有 0.28。降密度而不是讓最佳化器壓制，因為大幅壓制正是三代 77% 命中率病灶的成因。

### 投注模式

三檔 buy **轉數相同（8 轉）**，只差**儀表板的起始存量 0 / 2 / 4**（首次爆炸覆蓋 1 / 2 / 3 輪）。

轉數相同是刻意的：這款的特色遊戲價值**隨轉數複利成長**（更多炸藥 → 更高階 → 每轉價值三倍），賣更多轉會讓價格階梯爆炸且無法閱讀。

### 事件協定

`reveal`（轉輪停下的盤面）→ `blastReels`（`reels` / `symbol` / `level` / `maxLevel` / `sticky`）。

**順序有意義**：先 reveal 再爆炸。反過來試過，reveal 會直接顯示填滿後的盤面，前端沒有東西可以「炸開」——它得被另外告知舊符號才能重建一個它從未收到的盤面。

### 前端

- `ReelBlast.svelte`（取代 `ReelSplits.svelte`）——三拍：蓄力（該輪變暗）→ 爆炸（白閃，同一幀換符號）→ 落定。全盤爆炸多停 620ms。
- `Symbol.svelte` 的半寬雙繪已移除。
- `blastLadder` 由 `sync_math_config.mjs` 從 `game_config.py` 取出寫進 client config，儀表板和規則畫面都從它推導，不另存一份。
