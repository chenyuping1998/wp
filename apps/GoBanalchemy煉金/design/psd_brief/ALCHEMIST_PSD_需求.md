# Go Banalchemy 煉金師人物 PSD 需求清單

> 2026-10-16 執行方式更新：使用者指定「素材從 Boomana 拿過來，換皮換裝扮」。目前已以 Boomana 分件 PNG／原骨架製作 v3，來源與重建方式見 `../ALCHEMY_ASSETS.md` 的「Boomana 分件換裝 v3」。以下是結構與驗收參考，不再以收到新 PSD 作為開始製作的前提。可編輯交付採獨立 PNG、骨架 JSON、atlas、生成原稿與確定性產生程式。

**目標：** 做一隻跟 GoBoomana「炸藥礦工猩猩」**結構完全相同**的分件煉金師，並完成可編輯、可在遊戲播放的骨架綁定。
**2026-10-16 補充硬性要求：人物必須有骨架。** 只有分件 PSD、合成 PNG、影片，或整張圖片的搖晃動畫，都不能作為人物最終交付。美術分件完成後仍須完成綁骨、附件／網格權重、動作與遊戲端驗收。

以炸藥人物的骨架與動作作為起點，保留遊戲使用的動作名稱，但必須重新檢查煉金師的袖口、長外套、燒瓶、捶胸接觸與投擲握點。不能假設套用舊動畫就能直接完成。

**為什麼要重畫：** 目前的煉金師 PSD 只有一張完整成品圖，裡面附帶的「左臂／右臂」等圖層只是同一張圖的長方形裁切，手臂和外套連在一起。手臂一轉，軀幹也被拉著變形，所以捶胸碰不到胸口（拳頭只移動 17–35px）、丟炸藥時手也甩不起來。炸藥人物的每個部位都是獨立畫好的圖層，所以能大幅擺動。

## 3. 畫法規則（最重要）

1. **每個部件都要畫完整，包括會被別層蓋住的部分。** 動作時部件會移開，被蓋住的地方會露出來。
   - 上臂：肩膀處多畫約 25px 伸進軀幹底下。
   - 前臂＋拳頭：上端多畫約 20px 伸進袖口裡面。
   - **軀幹：手臂後面的外套側邊、腰側要完整畫出來**，不能因為被手臂擋住就留空或只畫一半。捶胸時手臂移到胸前，原本手臂的位置會露出軀幹側邊。
   - 大腿上端伸進軀幹（腰帶）底下約 20px；小腿上端伸進大腿底下；靴子上緣伸進小腿底下。
   - 脖子伸進立領底下。
2. **長外套要分段。** 炸藥人物的軀幹在胯部就結束，腿是分開的。煉金師的長外套如果從軀幹一路畫到膝蓋，抬腿時會撕開，所以：
   - 軀幹層（`torso_0_trunk`）只到腰帶／胯部。
   - 胯部以下的外套分給左右大腿層，或放進 `extra_coat_tail_L/R`。
3. **邊緣乾淨：** 透明處 alpha 必須是 0（不要有半透明的霧）；不要整片外光暈、不要跨部件的投影。
4. **不要畫發光效果：** 護目鏡鏡片、燒瓶可以有反光，但不要外發光（遊戲裡另外處理）。
5. **左手要能握試劑瓶：** 左拳在握點 (118, 576) 呈握拳、拳心略朝內，丟擲動作會把試劑瓶放在這裡。
6. **疊回去要和整張圖一樣：** 所有圖層照順序疊起來，要和成品圖看不出差別（參考 `ref_boom_full.png` 左右兩張）。

## 6. 骨架與動作（必須完成）

### 骨架結構

- 沿用遊戲命名：`root → hip → torso → head`；頭下有 `jaw`、`banana`、護目鏡／帽子附件。
- 左右手臂各自使用 `armL/R → armL/R_fore → armL/R_hand`，肩、肘、腕均為獨立關節。`prop` 掛在 `armL_hand` 下，並明確標記左手握點。
- 左右腿各自使用 `legL/R → legL/R_calf → legL/R_foot`，由 `hip` 帶動，髖、膝、踝均可獨立檢視。
- 長外套下襬、腰掛燒瓶、試管、護目鏡、香蕉與毛髮須以附屬骨頭／適當權重跟隨；不得用這些附件的物理效果拉扯手臂或軀幹。
- 手臂、腿與軀幹分件必須實際掛到對應骨頭。柔性區域可用加權網格，但不能再用一張全身成品圖，靠局部權重模擬所有大幅手臂動作。
- 以第 1 節的畫布關節座標為設定姿勢基準；若交 2 倍解析度，座標與縮放需一致換算。畫布左上座標與遊戲骨架座標的轉換必須記錄。

### 動作與接觸點

| 動作名稱 | 驗收重點 |
|---|---|
| `idle` | 自然呼吸、重心與附件輕微跟隨，可連續循環 |
| `cheer` | 手臂有明顯抬起／收回與軀幹配合，肩肘腕相連 |
| `chestbeat` | 左右拳確實移到胸前，接觸胸口後回收；不能只有前臂原地晃動 |
| `throwit` | 清楚蓄力、甩臂、離手與收勢；藥劑離手前跟隨握點，離手後不再黏手 |
| `nod` | 頭部點頭，頸部與領口不撕裂 |
| `flinch` | 可讀的受驚反應，四肢不折斷或瞬間跳位 |
| `alert` | 警戒姿勢與待機有清楚區別，能平順回待機 |
| `glance` | 張望動作，眼神／頭部方向清楚 |
| `flutter` | 衣襬、瓶罐、護目鏡與毛髮的附屬動態，可疊加主要動作 |
| `blink` | 眼皮半閉／全閉／張開，隨頭部移動，不漂離臉部 |

投擲離手時間沿用遊戲現有 **380ms**；如需更改，需同步更新動作、道具顯隱、出手位置、音效與轉場時序。捶胸的拳頭接觸位置及時間須依新版實際骨架重新量測，不沿用舊全身網格的數值。

### 技術與驗收條件

- 目前專案使用 `@esotericsoftware/spine-pixi-v8`／`spine-core` **4.2.74**；正式 Spine 匯出須選相容的 4.2 格式。其他產生方式也須在此專案 runtime 實測，不能只證明 JSON 有骨頭欄位。
- 每個分件都有正確附件、貼圖區域與繪製順序；停用任一手臂時，身後的軀幹完整，肩部／袖口／腰際無破洞。
- 以設定姿勢的骨段長度作基準，動作中的肩肘腕、髖膝踝骨段長度偏差不超過 5%；不能用拉長手臂來碰到胸口。關節角度須符合新版角色設定姿勢與實際分件，逐格檢查，不能只把角度限制調大來通過。
- 加權區域不得翻面；身體網格三角形面積維持設定姿勢的 50–160%。分件大幅旋轉仍需檢查關節覆蓋、穿插與剪影，數值通過不代表視覺驗收通過。
- 驗證所有主要動作，以及主要動作加 `flutter`／`blink` 的組合；檢查循環接縫、動作切換、回待機、一般速度與 turbo。
- 新版到件後先輸出到獨立資料夾驗收，再接回正式人物。現有 `check_alchemist_mesh.mjs` 與 `measure_alchemist_cues.mjs` 依賴舊 `alchemy_body` 全身網格，需配合新版分件骨架調整，不能直接宣稱沿用即可驗收完成。
