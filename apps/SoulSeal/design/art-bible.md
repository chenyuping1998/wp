# Soul Seal 美術聖經

道士收妖。夜、霧、燭火、符咒。

> **本文件已依實際交付的美術修訂（2026-08-22）。**
> §5.2 與 §5.3 是已定案的事實，其餘仍是規格。

這份文件的用途是讓美術產出**可被驗收**——每一條都要能回答「這張圖對不對」。
不要把它當靈感板看。

---

## 1. 一句話定調

> 深夜山廟，法壇已擺開。妖從暗處被逼出來，道姑一葫蘆收走。

不是恐怖片。是**志怪**——有壓迫感但不噁心，有神秘感但看得清楚。

**已交付的美術定下了實際調性**，比本文件原本設想的更華麗：
厚金屬框、寶石鑲嵌、飽和的紫／紅／金／綠、painterly 上色。
路線是「東方奇幻精品」而不是「陰森法壇」。
以下的配色與景深規範仍然適用，但**環境的華麗度要往交付的符號靠**，
否則符號會浮在一個比自己樸素太多的場景上。

**遊戲裡不使用中文字。** 低分符號是 A K Q J（+ 待補的 10），
不是原先規劃的五行漢字。由 `design/check_no_cjk_art.mjs` 守著。

## 2. 配色系統

### 2.1 三軸配色

整個畫面由三組顏色構成，各有嚴格的職責範圍。

**冷軸（環境，佔面積 ~65%）**

| 名稱 | Hex | 用途 |
|---|---|---|
| `night-deep` | `#0B1420` | 最遠的夜空、畫面四角的 vignette |
| `night-mist` | `#16283A` | 山霧、遠景輪廓 |
| `jade-wall` | `#1E3A3C` | 轉輪底板的青磚牆（中層） |
| `jade-lit` | `#2E5654` | 青磚被燭光打到的面 |
| `spirit-cyan` | `#4FD1C5` | **妖的靈光**。只給妖用，環境不得出現 |

**暖軸（法壇與燭火，佔面積 ~25%）**

| 名稱 | Hex | 用途 |
|---|---|---|
| `wood-dark` | `#3A2418` | 桃木樁、案桌暗面 |
| `wood-mid` | `#6B4226` | 桃木亮面、幡旗桿 |
| `brass` | `#A8763E` | 香爐、燭台、羅盤 |
| `brass-hi` | `#D9A85C` | 銅器高光 |
| `candle` | `#FFCB6B` | 燭火本體與其光暈 |

**金錢軸（獨佔，佔面積 <5%）**

| 名稱 | Hex | 用途 |
|---|---|---|
| `talisman-yellow` | `#F2D544` | 符紙底色 |
| `cinnabar` | `#C8102E` | 硃砂朱批、金額數字描邊 |
| `cinnabar-hi` | `#FF3B4E` | 金額數字的內側亮邊 |

### 2.2 鐵律

> **`talisman-yellow` + `cinnabar` 這組對比，全作只准出現在「身上有錢的東西」上。**

意思是：符紙金額、道士收取時的飛行數字、贏分面板。
其他任何地方——燭火、幡旗、道士的衣服、UI 按鈕——一律不准用這組。

燭火是 `candle #FFCB6B`，跟 `talisman-yellow #F2D544` 明顯不同色相（橘 vs 黃綠），
放在一起不會混淆。這是刻意留的間距，不要在製作中把它們調近。

同理：**`spirit-cyan` 只屬於妖。** 環境不准有青綠色的光。
玩家要能在餘光裡靠顏色分辨「哪個是妖」。

### 2.3 光源

單一主光源：**法壇上的燭火**，位於畫面下緣中央偏左，色溫暖。
所有法壇道具的高光都朝這個方向。

次光源：**妖的自體靈光**，冷青，只照亮妖自己與它腳下極小範圍。

天空不提供光。夜是暗的。

## 3. 三層景深

| 層 | 內容 | 明度範圍 | 飽和 | 細節密度 |
|---|---|---|---|---|
| **遠** | 山影、霧、殘月、廟脊剪影 | 15–35% | 低（去飽和到近灰） | 低，只有剪影 |
| **中** | 轉輪底板：青磚牆 + 燭光暈 | 20–40% | 中低 | 中，有磚縫與苔痕但不搶戲 |
| **近** | 法壇：案桌、香爐、燭台、桃木樁、幡旗 | 10–70% | 高 | 高，最精細 |

**中層壓暗的做法**：青磚牆本體 `jade-wall`，中央疊一層由 `candle` 出發的
徑向漸層（opacity 12–18%），邊緣自然變暗。**不要用純黑遮罩**——
純黑會讓畫面死掉，有材質的暗色才有空間感。

**近層形成 vignette**：法壇道具從畫面四邊往內延伸，明度最低，
自然把視線鎖在盤面中央。這是構圖手段，不是後製的暗角濾鏡。

## 4. 框架 = 法壇

**這是本作最重要的結構決定：轉輪外框不是 UI，是場景裡真實存在的法壇。**

```
        ┌──────── 符咒欄（頂端橫木，12 個符位）────────┐
        │                                              │
  幡旗  ├──┬──┬──┬──┬──┐                        ┌──┐  幡旗
  ┃     │  │  │  │  │  │   5×3 盤面             │  │     ┃
  ┃     │  │  │  │  │  │   （青磚牆底）          │  │     ┃
  ┃     ├──┴──┴──┴──┴──┘                        └──┘     ┃
  桃木樁└──────── 案桌檯面（木紋，前緣有反光）──────┘   桃木樁
        香爐(左)      羅盤(中)      燭台(右)
```

| 位置 | 道具 | 機能 |
|---|---|---|
| 頂端橫木 | 12 個符位，第 5/9/12 位是金色符 | 免費遊戲進度軌 |
| 左右立柱 | 桃木樁，纏紅繩，掛銅鈴 | 盤面邊界 |
| 左右外側 | 幡旗，**只有紋樣不寫字**（不用漢字） | 畫面邊界，可微幅飄動 |
| 下緣 | 案桌檯面，木紋橫向 | 盤面底座，前緣有燭光反射 |
| 案桌上 | 香爐（左）、羅盤（中）、燭台（右） | 環境敘事，香爐冒煙 |

**驗收標準**：把盤面上的符號全部拿掉，剩下的畫面應該仍然是一個「看得懂的場景」。
如果拿掉符號後剩下的東西像是一個空的 UI 面板，那就做錯了。

## 5. 符號

### 5.1 階級用材質區分，不用大小

三個階級，尺寸一致（單格 200×200），靠**材質複雜度**與**是否有容器**分級。

| 階級 | 符號 | 材質 | 容器 |
|---|---|---|---|
| 低分 | L1–L5 | 單一材質、單光源、色相編碼 | 無 |
| 中分 | H1–H4 | 全繪製、有高光與次表面散射 | 無 |
| 特殊 | M / C / S | 全繪製 | **有**：符紙、葫蘆光暈、金框 |

### 5.2 低分符號 L1–L5

**已定案，美術已交付 L1–L4。**

| 代號 | 字 | 主色 | 狀態 |
|---|---|---|---|
| L1 | **A** | 深紅／紫，金邊 | ✅ 已交付 |
| L2 | **K** | 綠／金，鑲綠寶石 | ✅ 已交付 |
| L3 | **Q** | 紫，金描邊 | ✅ 已交付 |
| L4 | **J** | 紅／金，卷草紋 | ✅ 已交付 |
| L5 | **10** | 待定 | ❌ **缺** |

**不用中文字。** 早期版本規劃的是五行桃木牌（金木水火土），已廢棄——
遊戲裡任何地方都不出現漢字。這條由 `design/check_no_cjk_art.mjs` 守著，
它會擋下藝術資產與非在地化字串裡的漢字（`src/i18n` 是合法例外）。

已交付的四個字都是**立體字**：厚金屬描邊、內填彩色浮雕紋樣、外圍柔光。
`10` 要照同一套語彙做，兩個字元的寬度是唯一的新問題——
不要為了塞進去而把字級縮小到跟其他四個不一致，寧可把兩字略微重疊。

### 5.3 中分符號 H1–H4

**已定案，美術已交付。**

| 代號 | 內容 | 主色 | 賠付 |
|---|---|---|---|
| H1 | 狐面（綠眼、金框、紫底） | 紫 + 金 + 綠 | 10× |
| H2 | 摺扇 + 五芒星 | 金 + 紅白扇面 | 4× |
| H3 | 陰陽 + 龍鳳圓牌 | 紫 + 藍 + 銀 | 4× |
| H4 | 銅鈴 + 紅繩圓牌 | 銅 + 紅 | 2× |

**剪影規範**：四個的基本形是 圓角方 / 圓角方 / 正圓 / 正圓。
H1 與 H2 都是方框、H3 與 H4 都是圓牌——**這是目前最大的美術風險**，
盤面上兩兩相似會降低辨識速度。做 M 與 C 時要刻意避開這兩個形狀。

眼睛與靈光用的青綠（H1 狐面）**不是** `spirit-cyan`——
`spirit-cyan` 仍然只屬於載體妖 M。這點在 M 做出來之前無法驗證，
交付時要並排比對。

### 5.4 特殊符號

**M — 載體妖（帶金額）**

```
   ┌─────────────┐
   │   妖的身體   │  ← 全繪製，帶 spirit-cyan 靈光
   │  ╔═══════╗  │
   │  ║ ×2.50 ║  │  ← 黃符貼在身上，硃砂寫金額
   │  ╚═══════╝  │
   └─────────────┘
```

- 妖身：統一造型（不要用 H1–H4 的四種），一個專屬的「小妖」設計，
  圓潤、無威脅感、略帶滑稽——它是要被收走的東西，不該讓人害怕
- 黃符：`talisman-yellow` 底，四角有燒焦痕，斜貼在妖的胸口
- 金額：硃砂 `cinnabar`，外描邊 `cinnabar-hi` 1px，書法感數字。
  面額 19 階，最高 1000×，位數變化大——
  **字框要能容納 `1000×` 到 `0.5×` 而不改變符紙尺寸**，
  用字級縮放而非換行。超長時縮寫成 2 位小數且必須**向下取整**
  （顯示值是給付下限，不得高於實付）
- 靈光：`spirit-cyan` 外發光，opacity 40%，**不要用 additive blend**
  （見 skill：mask 內的 additive 畫不出來，要烘進貼圖 alpha）

**C — 道士（收集者）**

**一張圖，不是三張。** 倍數共 8 階（×1 ×2 ×3 ×4 ×5 ×10 ×15 ×20），
全部用同一張圖，數字由程式疊在下緣。

早期規劃是三階美術（小道士／道長／天師）依倍數換圖，已取消——
參考作用一張漁夫做完同樣的事，×2 跟 ×20 長得一樣，只有數字不同。
數字已經把資訊講完了，而三張必須共用輪廓的人物是三倍的工。

- 直立全身人物，手持葫蘆前伸，**無外框**
- **下緣四分之一要留乾淨**：倍數數字畫在那裡，下擺太花會讀不出來
- 倍數數字用 `brass-hi` 金色，**不是** `talisman-yellow`——
  道士的倍數是乘數不是錢，色彩上要跟金額區隔
- 要跟 W（鳥居巫女）分得開：W 是有框半身像，C 是無框全身人物

**S — Scatter（符詔）**

一張懸浮的敕令符，比 M 的黃符更大更正式，四邊有雲紋。
用 `talisman-yellow` 但**加金邊**與旋轉光暈，跟 M 的符區分。

### 5.5 符號製作規格

| 項目 | 值 |
|---|---|
| 單格輸出 | 200×200 px，PNG 帶 alpha |
| 內容安全區 | 中央 176×176，四邊各留 12px |
| 描邊 | 外 4px `#1A1008`，內 1px 亮邊 |
| 光源 | 左下 45°，燭火色溫 |

| 輸出路徑 | `static/assets/sprites/soulSealSymbols/` |

## 6. 字體

- **顯示字（金額、倍數、標題）**：需要一套有書法骨架但可讀性夠的字。
  **不能用系統預設**（review 明確退過件）。
  方向：楷書骨架 + 加粗 + 硬邊，不要用行草（看不清楚）。
- **UI 字**：無襯線，中英日韓都要有字符覆蓋（`check_font_coverage.mjs` 會驗）。
  這是**在地化**需求，跟「美術不用漢字」不衝突——玩家把語言切成中文時，
  UI 當然要顯示中文。禁止的是把漢字烘進美術資產。
- 標題 logo：**英文 "SOUL SEAL"**，不用漢字。金屬立體字，硃砂印章底，
  白色外描邊拉開與背景的對比。造型語彙跟已交付的 A K Q J 對齊。

## 7. 演出

### 7.1 分級原則

參考作的克制值得學：base game 中獎只有一條線 + 一個數字，
把所有 juice 留給 feature。本作沿用。

| 事件 | 演出強度 | 內容 |
|---|---|---|
| 一般連線 | 低 | 見 §7.1a |
| 妖落定 | 低 | 妖出現時一次 `spirit-cyan` 脈衝，0.3s |
| 道士落定 | 中 | 道士入場，法器亮起，鎮鈴響一聲 |
| **收取** | 高 | 見 7.2 |
| 符位貼滿 | 高 | 符咒欄整排發光，幡旗揚起 |
| 進入免費遊戲 | 最高 | 霧散、燭火轉青、法壇浮起 |

### 7.1a 一般連線（照參考作，已逐幀比對）

三個元素，缺一不可：

1. **極細的橘金色折線** `#EFB938`，線寬約格子的 1.8%。
   單線，**沒有暗色襯底、沒有節點圓點**。
2. **中獎符號放大並持續呼吸** — 落定時彈一下（+30%），然後小幅脈動（±10%）。
   **這就是律動感的來源，不是線在動。**
3. **非中獎符號調暗**。整個效果靠的是**對比**，不是往上加東西。

正中央白色數字配深色描邊。**不加粒子、不震動。**

**這段修過兩次，兩次都是因為只看單張靜態幀。**
第一版把線畫得又粗又有襯底還加了節點圓點，而且判斷成「不調暗」——
抽連續幀來看，線是髮絲細的、沒有圓點，而且非中獎符號明顯變暗、
中獎符號明顯變大。**靜態幀看不出律動。**

`design/preview_win_line.mjs` 可以驗線寬（驗不了脈動，那要跑起來看）。

### 7.2 收取演出（本作的招牌動作）

這段是整個遊戲的賣點，時序要精確：

```
t=0.00  道士停穩，葫蘆口朝盤面，塞子彈開
t=0.15  葫蘆口出現吸力漩渦（spirit-cyan）
t=0.30  最左的妖開始被拉扯，身體變形
t=0.45  第一隻妖被吸入，身上的符脫落並飛向道士
t=0.45+ 之後每隻妖間隔 0.12s 依序收取（左→右，上→下）
        每收一隻，葫蘆脹一下，音高遞增
t=末+0.2 所有符匯聚到道士頭上，疊成一疊
t=末+0.4 道士倍數印章蓋下（brass-hi），符疊×倍數
t=末+0.7 總額以硃砂數字放大彈出，塞子塞回，鎮鈴收尾
```

**兩條硬性要求**：

1. **收取順序 = 數學結算順序。** 不准為了好看改順序。
2. **葫蘆吸力光暈掃過的範圍 = 數學實際評估的範圍。**
   如果動畫暗示某幾格被涵蓋，那幾格就必須真的被算進去。
   （review-log：這種不一致在審核眼裡就是賠付 bug）

### 7.3 環境 idle 動畫

畫面不能死。低成本的持續動作：

- 香爐的煙，緩慢上升並飄散（loop 8s，不對稱以免看出循環）
- 燭火晃動，連帶所有銅器高光微幅明滅（loop 2.3s）
- 幡旗下擺輕飄（loop 4.1s）
- 遠景霧橫向緩移（loop 20s）
- 偶發：一隻紙鶴飛過遠景（每 40–60s 一次，隨機）

三個 loop 的週期刻意互質，避免整體節奏對齊被看穿。

## 8. UI

- 底部 bet bar 是**唯一不融入場景**的元素。深色半透明條，功能區與表演區切乾淨。
  排列依 review-log：左邊選單與讀數，右邊 bet / stepper / spin / autoplay / turbo。
- **Buy bonus 用不同形狀**——圓形銅錢造型，孤懸左下，跟其他方形 UI 區隔，
  且刻意遠離每幾秒就要按一次的 spin 鍵。
- **不准用 emoji 圖示**（review 明確退過）。所有圖示自繪。
- Spacebar 綁 spin。
- 所有 modal 要在最小支援尺寸與 popout 下測過。

## 9. 產出管線

沿用 EmberForge 的做法：SVG 在 `.mjs` 產生器裡以程式描述，用 resvg 轉 PNG。

```bash
node design/generate_theme_soulseal.mjs E:\stake\tools\gen
```

規範：
- 亂數要 **seeded**，不要用 `Math.random()`。每次 build 產出不同的圖無法審查。
- resvg 的 filter region 保持在 ±200% 以內，超過會直接 panic。
- `DUMP_SVG=1` 會把原始 SVG 寫在 PNG 旁邊，除錯用。
- **保留所有可分層的原始素材。** 封面被退件要求重新構圖時，
  壓平的圖沒辦法把裁掉的像素還回來。
